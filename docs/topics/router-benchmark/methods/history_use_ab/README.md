# 历史信息的两种新用法：a 学「怎么掂量」、b 管校准（2026-11-16 傍晚）

背景：档案之外加 4 个完整历史案例只多 +0.02（不显著）。crc 问「历史是不是还没用好」。这里试两种不把历史当案例喂的用法。
数据：旧题 157 道有档案（DS 历史成败），其中 146 道有公开 14 家成绩。两折按仓库切（refjudge/repo_fold.json），一折学、另一折评。
脚本路径按 scratchpad 布局写（与 dossier_v4 相同）；结果原文见 *_result.txt。

## b 历史管校准（不花调用）— calib_hist.py
判断者普遍偏悲观：平均预测失败率 0.36~0.45，DS 实际 0.255。用另一折的历史失败率把整体偏置平移（base）或做 Platt 缩放：

| 做法 | Brier 原始 → 平移 | ECE 原始 → 平移 | Brier 差 95%区间 |
|---|---|---|---|
| 档案 + Haiku | 0.211 → 0.187 | 0.147 → 0.067 | [−0.045, −0.001] |
| 档案 + Sonnet | 0.185 → 0.172 | 0.110 → 0.061 | [−0.028, +0.004] |
| 档案 + 案例 + Haiku | 0.231 → 0.192 | 0.193 → 0.095 | [−0.068, −0.011] |
| Sonnet 读仓库（强基线） | 0.176 → 0.174 | 0.099 → 0.073 | [−0.008, +0.004] |
| 只报历史失败率、不看题 | 0.190 | 0.002 | — |

读法：历史在「概率报准」上有明确作用，ECE 约减半；加了案例的组最悲观，校准收益最大（案例让判断者更悲观）。但校准后 Brier 只略低于「只报历史失败率」——说明排序信息（AUC≈0.63~0.70）换成概率后的增量本身不大。

## a 让历史学每节权重 — secrisk.py（Haiku，157 次）+ fit_secrisk.py
判断者对档案 7 节各打风险分 r1~r7，再在另一折上用 DS 历史成败（逻辑回归）或 14 家公开成败（岭回归）学权重。

| 组合方式 | 与 14 家难度相关 | 14 家平均 AUC | DS AUC |
|---|---|---|---|
| 判断者自己的整体 p_fail | 0.472 | 0.697 | 0.674 |
| 7 节等权平均 | 0.435 | 0.674 | 0.620 |
| 学权重：DS 历史 | 0.412 | 0.673 | 0.682 |
| 学权重：14 家公开历史 | 0.361 | 0.647 | 0.683 |
| 学权重：DS 历史 + 整体 p_fail | 0.438 | 0.686 | 0.686 |

学到的权重（DS 历史）：题面 0.92、边界 0.69、难点 0.57、约定 0.44，代码位置/并列为负。相关度差（学权重 − 整体）：DS 历史 [−0.15, +0.03]，公开历史 [−0.21, −0.01]。
读法：**负结果**。判断者自己的整体掂量不输于用 70 多道历史题学出的权重；单节最有用的是 r5 边界（14 家 AUC 0.692）、r1 题面（DS AUC 0.713），但合起来学不出更好的组合（每折约 70 题、7 个强相关分，权重不稳）。

## 附：有没有 DS 特有的信号 — section_specific.py
按公开难度分 4 层、层内算各节对 DS 成败的 AUC：最高 r1 题面 0.558、整体 p_fail 0.562，其余在 0.37~0.55。公开难度本身对 DS 的 AUC 为 0.91。
读法：控制题目本身难度后，档案各节几乎看不出 DS 特有的弱点——DS 挂主要因为题难、各家共享。这解释了为什么 DS 自己的历史在排序上帮助小：历史能给的「DS 特有」信息本来就少。

## 结论（写进论文 4.4/5.x）
1. 历史的确定作用在校准（b）：把整体偏悲观拉回来，ECE 约减半。
2. 用历史学「怎么掂量」（a）没有超过判断者自己的整体判断；瓶颈不在权重。
3. 单一执行者（DS）上，难度之外的「特有毛病」信号很弱；历史在排序上的价值要到多执行者（rebench 针对执行者组，已冻结）才能检验。
