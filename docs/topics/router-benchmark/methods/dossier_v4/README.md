# 方法 v4：仓库档案 + 完整案例（2026-11-16）

## 一句话
贵模型只做一次「按难点查证」，写成一份结构化仓库档案；判断交给（可以便宜的）模型，看「完整题面 + 档案 + 几个同格式的历史案例」给出失败概率。

## 为什么这样设计（前几版的教训）
- v1 经验卡、v2 特征打分、v3 一行案例都没提升：信息被压缩得太狠。十几万字的代码只剩 3 条线索，历史案例只剩一行结论。
- 实测：同一个判断模型，看 3 条线索 vs 自己读仓库，相关度 0.35 vs 0.45（14 家公开难度，144 道）。损失在「查」这一步。

## 流程
1. **查证 → 仓库档案**（build_dossier.py，Sonnet，读修复前快照 ≥10 次检索，≤2500 字，不给概率、不看答案）。固定 7 节：
   1 题面要点（复现、期望、修法建议原句） 2 相关代码（文件:行号） 3 并列与牵连（并列实现、成对方法、多个调用点） 4 现有测试与约定（断言原文、规范、是否与题面冲突） 5 边界与隐含要求 6 改动规模 7 难点一句话
   例子：example_dossier_gson-1100.md（查出了题面没提的「读方向同样有 null 问题」，正是 DS 当年挂的原因）。
2. **案例库**（v4.py note）：历史题用同格式的档案，加事后注记——标准修复改了哪里、DS 做对/做错了什么、档案里本可以看出的信号。挂的和过的都有。
3. **挑案例**（v4.py select，Haiku）：按两边档案的「难点一句话」挑 2 个挂 + 2 个过最像的。
4. **判断**（v4.py judge，Sonnet 或 Haiku）：完整题面 + 新题档案（+ 4 个完整案例）→ p_fail 与一句理由。
- 每次判断约 1.5~2.5 万字输入。建档案每道约 35 秒、约 0.18 美元额度。

## 小样结果（28 道旧题，分开仓库取案例）
相关度 = 与 14 家公开 AI 平均难度的秩相关；括号 = 对 14 家各自成败的平均 AUC。

| 做法 | Sonnet 判 | Haiku 判 |
|---|---|---|
| 3 条线索 | 0.19 (0.58) | 0.27 (0.60) |
| 仓库档案 | 0.44 (0.69) | 0.53 (0.74) |
| 档案 + 4 个完整案例 | 0.44 (0.69) | 0.56 (0.75) |
| Sonnet 自己读仓库直接判 | 0.46 (0.67) | — |

读法：查得全是最大提升；有好档案后 Haiku 判得不比 Sonnet 自己读仓库差；完整案例增益小。样本小，正在扩到 144 道。
