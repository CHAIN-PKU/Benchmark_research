# DeepSeek 挂题判断经验（本批 71 题，整体挂率 27%）

## 一、DS 什么时候挂、什么时候过

只列挂侧与过侧挂率差距明显的信号（差距不明显的，如“并列实现”“根因是否单点”，在本批几乎没有区分力，不要单独当依据）。

**1. 开放式设计 vs 补一个确定的点（挂 10/27=37% vs 6/32=19%）**
- 挂：需自行设计新接口、跨层传参，或“拒绝非法输入”这类边界难枚举的要求。
- 过：只补一个缺失分支、替换一处判据、加一行默认值。
- 对照：fluentd-3641（非法或缺端口要抛 ConfigError，不能回退 split）挂；three.js-27395（Sphere 构造器加一行 isSphere，照抄 Box3）过。

**2. 期望行为靠猜 vs 有复现/先例可抄（挂 9/25=36% vs 8/38=21%）**
- 挂：期望语义含糊（标量还是数组、非法形态怎么处理），无对照输出，或仓库约定与题面字面相反。
- 过：题面给复现与期望输出，或仓库内有同类先例。
- 对照：phpspreadsheet-3570（字面取首元素，但仓库约定数组逐元素展开）挂；django-12304（题面直接给出 do_not_call_in_templates）过。

**3. 现有测试固化旧行为或无可参照断言（挂 9/18=50%，本批最强信号）vs 有紧邻同类用例且方向一致（6/41=15%）**
- 挂：现有测试固化了与期望相反的行为，诱使改错层、改断言迎合。
- 过：有紧邻的同类断言，隐藏测试形态可推。
- 对照：fluentd-3640（现有测试固化实际间隔序列，只能改求和，不能动 calc_interval）挂；fluentd-4598（堆栈直指 `path <<`，改成 `path +=` 即可）过。

**4. 存在波及既有行为的“低成本捷径”（挂 14/42=33% vs 4/19=21%）**
- 挂：改共享入口、通用构造器或运行时间隔看似最小，却连带破坏其他分支。
- 过：自然改法局部，影响面限于目标路径。
- 对照：sphinx-8638（去 rolename 与收紧 find_obj 两条路，选错层）挂；fpm-1850（只在 Empty.initialize 里 super 后设值）过。

**5. 依赖外部不确定因素（挂 3/13=23% vs 9/41=22%）：无区分力，不要作为判据。** 但有一种除外：隐藏测试对 mock 方式有唯一要求。对照：django-11848（测试只 mock utcnow，必须用 utcnow().year）挂；fluentd-4598（纯函数式、仓库内闭环）过。

**6. 题面位置不等于真实落点（挂 8/25=32% vs 8/35=23%）**
- 挂：题面点名位置与落点不符，如要改枚举源头而不是过滤处。
- 对照：sphinx-8548（要改 get_class_members 枚举，改过滤处是 WRONG_LOC）挂；fpm-1850（题面位置即落点）过。

## 二、判断者常犯的误判

### 漏报（给低了，实际挂）：被“风险已写进档案”或“改动很小”骗了
1. **档案写了并列/成对实现，就以为 DS 会覆盖。**
   - 步骤：数出并列点个数。题面只点一个、各点独立赋值、且并列点无现有测试时，调高。DS 常只改最显眼的一处。
   - 对照：three.js-26589（Line/Points/Sprite 的 copy 各自独立，只改 Mesh）挂；three.js-27395（单一构造器，无并列）过。
   - 对照：gson-2061（只改 JsonReader，漏 JsonTreeReader 的 hasNext）挂，三家判断者都给低。gson-1100（题面只讲 write 的 NPE，漏 read）同理。
2. **题面只讲一侧，漏掉读写对称的另一侧。**
   - 步骤：凡是 write/read、序列化/反序列化成对的类，先问隐藏测试会不会测另一侧。
3. **档案列出的“边界/非法输入”被当成次要细节。**
   - 步骤：档案出现“格式错误、无端口、非法形态”，就按隐藏测试的显式用例处理，看修法是否要求校验并报错。
   - 对照：fluentd-3641（要求抛 ConfigError）挂；fluentd-4598 无此类要求，过。
4. **“改动很小”但需区分多个相近条件。**
   - 步骤：数条件个数。blank/required/widget 这类要同时区分的，调高。
   - 对照：django-12406（要区分 blank 与 RadioSelect，横跨两处）挂；django-12304（唯一陷阱已点明）过。
5. **多条可行修法且测试断言结构形态。**
   - 步骤：看测试断言的是节点类型还是结构。多条路时，判 DS 选错层的概率，不能因根因已定位就压低。
   - 对照：sphinx-8638 挂。

### 误报（给高了，实际过）：被“诊断难、不确定”吓到
1. **“需实测、根因未证实、难复现”不等于实现难。**
   - 步骤：先看档案是否给出文件、行号或函数级落点，改动是否局限在 1 个文件的几行。若是，则不因诊断难度给高。
   - 对照：fluentd-4030（档案已定位到 find 返回 nil 解引用，加 nil 判断）、micropython-13569（定位到 compile_try_finally 预留不足）都过。
2. **仓库内有同类前例就压低。**
   - 步骤：搜档案里的“前例/模板”，有同 handler、同函数的同类修复，如 lombok-3097、vue 的 #11188、rubocop 已有 wrap 写法，则按照抄处理。
   - 对照：lombok-3326 过；lombok-3371（要区分最外层和内层数组注解）挂。
3. **“隐藏测试可能逐字符匹配”“题面有两种写法”。**
   - 步骤：看这些写法是否等价示例，仓库有无已有惯例。有则取最自然的那个，不上调。
   - 对照：rubocop-13687、lombok-3674 过。
4. **“要改多个 port、多层”的想象性复杂度。**
   - 步骤：先看测试实际跑哪个 port、断言多强。
   - 对照：micropython-12158 过。
5. **单点补丁的想象性冲突。**
   - 对照：faker-2705（单方法约十行，复现明确）过。

### 判断者共同的偏差（DS、GLM 都出现）
- 已查到根因、改动局部时仍给 0.45～0.7（immutable-js-2005/2006、lombok-3350、fluentd-3631），实际近乎全过。
- 反过来，查到了并列漏改（gson-2061）、缺校验（fpm-1829）、测试与题面冲突（rubocop-13560）、需补依赖并显式实现（carbon-2813）时，只给 0.2～0.3，实际约半数以上挂。
- 操作：先给“落点是否唯一确定”打分，再单独检查四件事：测试是否固化旧行为、是否有对称侧或并列点漏改、是否要求新校验、有无多条修法。有任一项，不低于 0.5。四项都没有，且落点在行号级，则不高于 0.2。
