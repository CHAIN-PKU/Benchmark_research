# DS 历史经验文案（动手前判断者用）

## 一、DS 大多数题怎么做对的（本批 86 题，整体挂率约 24%）

**默认立场：偏向「能做对」。只有出现下面第二节的明确挂侧信号，才上调。**

DS 稳定做对的情形，共同点是：**症状点即修改点、期望行为唯一、改动只有几行、有东西可照抄或可对拍。**

1. **期望唯一明确，不与旧测试冲突（历史挂 9/55，约 16%）。** 有具体输入输出或症状，只需新增或保持行为。
   例：gin-4003，栈指向 gin.go:693 `len(t)-1`，修法唯一，测试只断言 404，过。
2. **根因定位到具体行或函数（历史挂 9/38，约 24%）。** 档案点名单一位置，没有第二个诱人落点。
   例：hugo-12768，根因是 gitHubAlertRe 大小写敏感，改一行 `(?i)`，下游已 ToLower，过。
3. **题面自带完整修法，且与测试无冲突。**
   例：jekyll-8167 题面直接给正则，只改 utils.rb 两行常量；gin-2121 题面给 3 行 diff，根因单点，都过。
4. **接口和输出由题面或现有 CLI 决定（历史挂 18/77，约 23%）。** 期望输出可以逐字对照。
5. **题面平台无关、无现成补丁，有可运行复现（历史挂 16/64，25%）。**
6. **单文件少量改动，调用点已逐一核对（历史挂 12/46，约 26%）。** 或者一处守卫覆盖全部路径。
7. **档案已定位根因，仓库里有同类现成修法可照搬。** 即使边界清单很长也能过。
   例：preact-4182，Suspense 钩子已有 `_dom/_children` 继承的参照，几行改动，过。
   例：jq-2750，根因精确定位到 FORK_OPT 回溯点泄漏，题面有明确期望输出，过。

**为什么能做对：** DS 擅长局部定位加小补丁。题面给了症状和期望、档案给了位置时，它几乎不需要做设计判断。

## 二、挂和过的区别（每条挂信号配一条过信号）

| 维度 | 挂信号（历史挂率） | 对应过信号（历史挂率） |
|---|---|---|
| 期望 | 含糊、多种合理解读，或与现有断言冲突、要改旧契约（9/20=45%） | 期望唯一，只新增或保持（9/55=16%） |
| 落点 | 多个看似合理落点：下游补丁还是上游根因，链接指向已支持模块（11/37=30%） | 档案锁定具体文件行，无第二落点（9/38=24%） |
| 泛化 | 只给一个例子，同类变体要自己枚举（12/49=24%） | 题面实例即全部情形，档案称无同类重复（4/25=16%） |
| 接口 | 要自设公开 API 或数字格式，测试直接断言（3/7=43%） | 接口由题面或现有函数给定（18/77=23%） |
| 对拍 | 无相关测试可参照（3/16=19%） | 档案引了具体断言行，知道改什么留什么（14/60=23%） |
| 误导 | 题面有现成补丁(>)、平台字样、规范链接（5/14=36%） | 平台无关、给根因或可运行复现（16/64=25%） |
| 状态 | 状态机、幂等、作用域栈、边界数值，档案仅作旁注（13/47=28%） | 单点条件或缺失分支，状态约束已被讲透（5/25=20%） |
| 牵连 | 多文件多入口，牵连面藏在别处且未核实（7/30=23%） | 调用点逐一核对，无牵连（12/46=26%） |

说明：对拍、牵连两行的总体挂率差距不大，不单独作为强信号，只作辅助。

**对照例子（挂 vs 过）：**

- **期望/误导（题面补丁与测试约定冲突）：** laravel-48573，题面补丁 `>=`→`>`，测试约定「恰好 TTL 秒即过期」要 `>=`，照抄即挂。gin-2121，题面补丁与测试一致，照抄即过。
- **平台字样：** bat-2650，标题写 "on Windows"，DS 把修复做窄，而测试在 Linux 跑，挂。gin-4003 无平台字样，过。
- **链接指向已支持项：** caddy-6345，链接指向已支持的 `tls internal`，DS 易改错指令，挂。hugo-12768，只有一个解析路径，没有第二落点，过。
- **泛化：** php-cs-fixer-7663，只给一例，漏了 `do-while`（`T_DO` 不在列表里），挂。hugo-12768 只有一个正则，没有并列变体，过。
- **最小修法代价是丢功能：** fmt-3750，回退无分组最省事，但 hex/bin/oct 要保留分隔符，挂。jekyll-8167 最小修法就是目标修法，过。
- **规范语义隐含：** fmt-3863，题面表格无引号，规范要求 `s` 带双引号，照抄表格即挂。jq-2750 有明确期望输出，过。
- **输出格式陷阱：** prometheus-10633，float64 用 `'g'` 会输出 `1e+06`，测试逐字比对，挂。gin-2121 无格式化问题，过。
- **被解耦的另一路径：** gin-3227，一行改动后 tree.go 对带参数路由缺 tsr，挂。gin-4003 单点修复，无另一路径，过。
- **耦合的输出修正：** caddy-5404，修掉 panic 之外，还要同步 finalizeHeredoc 的尾换行和 NumLineBreaks，挂。hugo-12768 一行改动无附带输出，过。
- **优先级覆盖：** jq-2728，NO_COLOR 放在 `-C` 之后会压过强制开色，挂。jekyll-8167 无优先级关系，过。

## 三、判断者常犯的误判

### A. 误报：把能做对的题判成会挂（约一半篇幅）

**被什么吓到：**
- 「定位难、边界多、隐藏测试严」这类泛化难度叙述（preact-4182 给 0.6，实际过）。
- 风险清单很长或牵连面很宽（jq-2750 给 0.6，laravel-51195 给 0.6，实际都过）。
- 「设计开放」的措辞（jekyll-8771 给 0.6，实际有几十行的全局方案可过）。
- 模板元编程、C++20/23 双失败路径（fmt-3158 给 0.7，实际改的是局部 SFINAE）。
- 担心接口命名或形状断言（bat-562 给 0.55，preact-3562 给 0.55，实际测试只验行为）。
- 档案点名嫌疑函数，却因「共享状态难定位」调高（hugo-12448 给 0.6，实际局部小改，过）。
- DS 和 GLM 当判断者时都有这种整体偏高的倾向（caddy-5626 给 0.6 和 0.45，caddy-5870 给 0.4，实际 14 家只有 2 家或 1 家没做对）。

**可操作的判断步骤：**
1. **先找落点。** 档案是否指向单文件单函数？是，则起点定在低位，不看难度形容词。
2. **找可照搬的东西。** 题面有补丁、复现、回归版本，或仓库内有同类修法，则再降。
3. **看隐藏测试验证什么。** 若只验行为（文件名被当文件、两个回调都触发），接口命名不确定不算风险。
4. **把风险清单逐条过滤。** 只保留能落到第二节八项挂侧信号的条目，「清单长」本身不加分。
5. **排除无关风险。** 生成文件不重建（jq-2598 实际构建会重新生成）、兄弟分支、wchar（fmt-3272），题面例子已正确就不要推断偏离。

**反例对照：** fmt-3272 被兄弟分支和 wchar 吓到给 0.6，14 家只有 2 家没做对。redis-11631 已定位到一行修复仍给隐藏风险 0.5，14 家 0 家没做对。

### B. 漏报：把会挂的题判成能过（约一半篇幅）

**被什么骗了：**
- **「改动只有一行或几行」。** bat-2650、gin-3227、caddy-6345 都因此被低估。代码量小不等于落点唯一。
- **档案说「已存在」或「不用处理」。** laravel-48573 档案说 `>` 已存在；laravel-46234 档案说尾斜杠「大概率不用处理」，实际是隐藏测试点。
- **「修掉 panic 就行」。** caddy-5404 实际要连带改输出和行数补偿。
- **「简单加个 case」。** prometheus-10633 实际卡在 `'g'` 格式化。
- **「模型会按规范做」。** jq-2728 档案已点名优先级，判断者仍给 0.35。
- **没掂量对最小修法的代价。** fmt-3750 档案列了「最小绕过=丢功能」，DS 会走最小绕过（GLM 当判断者给 0.2，14 家 12 家没做对）。

**可操作的判断步骤：**
1. **对着题面补丁核对测试约定。** 补丁方向与锁定测试的边界（`>=` 还是 `>`）冲突时，按挂处理。
2. **扫题面字面诱导。** 平台字样、指向已实现选项的链接、规范链接，每命中一项上调。
3. **只给一例时，枚举同类全集。** 同类关键字（do/elseif/else）、成对 API、并列写法，有未列入的就上调。
4. **看有没有两个来源的字符串或 URL 比较。** 有则要想到尾斜杠等规范化。
5. **档案里出现「格式化」「优先级」「补偿」「最小修法代价」等字样时，把它当主线，而不是旁注。** 档案若点名了这类陷阱，不要默认 DS 会处理。
6. **查被解耦或被复用的另一条路径。** 一行改动改变了调用关系时，要查另一路径是否对所有类型成立（gin-3227 的 tree 层）。
7. **查 DS 最省事的做法会不会丢功能。** 会，则给高概率。

**反例对照：** caddy-6115 里 DS 判断者看到了 `Secure: r.TLS != nil` 的做法，却当成与题面冲突，只给 0.3，14 家有 11 家没做对。GLM 当判断者根本没想到 Secure 要依赖 TLS，给 0.2。线索看到了就要用，不要当作冲突排除。

## 四、使用顺序

1. 先从偏低的起点出发（约 0.2）。
2. 依次扫第二节八项挂侧信号，以及第三节 B 的七步，每命中一项上调。
3. 命中多项，或命中「题面补丁与测试冲突」「最小修法丢功能」「格式化」这类强信号，再给高概率。
4. 一条都没命中就别硬找理由，保持低概率。
