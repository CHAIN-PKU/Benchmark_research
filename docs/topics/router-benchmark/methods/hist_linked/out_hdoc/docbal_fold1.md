# DS 历史经验文案（71 题，整体挂率 27%）

## 一、DS 大多数题怎么做对的

本批挂率只有约 25%。**默认偏向「能做对」**，只有出现明确的挂侧信号才上调。

DS 稳定做对的情形，以及原因：

1. **根因单点、落点就是题面位置**（过侧挂 8/35，约 23%）。堆栈直指出错行，改一处就行。
   - 例：fluentd-4598，`path << '/'` 原地追加，改成 `path +=` 即可。
   - 例：fpm-1850，`Empty.initialize` 里 super 后设 `all`。
2. **有现成先例可照抄**（挂 8/38）。仓库里同类写法已经存在。
   - 例：three.js-27395 照 Box3/Plane 加一行 `isSphere=true`。
   - 例：rubocop-13687 已有 wrap 加括号的先例。
3. **补一个分支、换一处判据或加一个默认值**（挂 6/32）。输出唯一，没有设计空间。
   - 例：django-12304 在元类里设 `do_not_call_in_templates`。
4. **仓库内闭环的纯函数式修复**（挂 9/41）。不依赖时钟、全局状态或第三方源码。
5. **有紧邻的同类测试**（挂 6/41）。DS 能推出隐藏测试的形态。

诊断难不等于实现难。判断者在这类题上最容易高估难度，见第三节。

## 二、挂和过的区别

每条列挂侧信号和过侧信号，括号内为历史挂率。

**1. 并列实现和消费点：「只改显眼的一处」**
- 挂侧：有并列副本、读写成对，或多个脏数据消费点，而题面只点一个。挂 8/29。
- 过侧：调用点汇聚到一处，或并列点已逐项列全、核实完毕。
- 判别：并列处各自独立赋值、无共用基类、无现有测试覆盖时，DS 会只改最显眼的。
- 挂：three.js-26589 只改 Mesh，Line/Points 的 `copy()` 漏改。gson-2061 只改 JsonReader，JsonTreeReader 漏改。
- 过：fluentd-4598 的 compat 版本无需改，没有并列。

**2. 多个落点：「落点与题面不符」**
- 挂侧：根因有多个候选，题面位置不等于真实落点，需自行推断改哪层。挂 8/25。
- 过侧：根因明确，档案已给出具体修改点。挂 8/35。
- 判别：看档案是否写了「两条可行修法」。若有，DS 常选错层。
- 挂：sphinx-8638 根因在字段定义的 rolename，DS 容易去改解析端 `find_obj`。sphinx-8548 要改成员枚举源头，改过滤处就是 WRONG_LOC。
- 过：fpm-1850 只有一个落点。

**3. 期望行为：「要靠猜」**
- 挂侧：语义含糊，无复现或对照输出。挂 9/25。
- 过侧：题面给出复现与期望输出，或有外部基准。挂 8/38。
- 判别：题面修法与仓库既有约定冲突时，以仓库约定为准，字面照做会挂。
- 挂：phpspreadsheet-3570 字面取首元素，但仓库约定是逐元素展开返回数组。
- 过：faker-2705 的复现脚本和意图明确，加数字并计入 min_length 即可。

**4. 现有测试：「固化旧行为或毫无参照」**
- 挂侧：测试固化了与期望相反的旧行为，诱导改错层。挂 9/18，这是区分力最强的一条。
- 过侧：有紧邻的同类用例，且与修复方向一致。挂 6/41。
- 挂：fluentd-3640 的测试固化了实际间隔序列，DS 改了运行时逻辑再改写断言。
- 过：vue-11739 有 #11188 现成模板。

**5. 修法：开放式设计 vs 补一个确定点**
- 挂侧：新增接口、跨层传参，或开放式「拒绝非法输入」。挂 10/27。
- 过侧：补一个分支或替换一处判据。挂 6/32。
- 判别：档案把「格式错误或无端口」列为边界时，那就是隐藏测试的显式用例，修法必须校验并报错。
- 挂：fluentd-3641 对非法 endpoint 要抛 ConfigError，DS 只让新输入能解析。
- 过：fpm-1850 只需一行赋值。

**6. 外部不确定因素：「只有唯一接口能过」**
- 挂侧：依赖 mock 时钟、全局状态或未读到的第三方源码。挂 3/13。
- 过侧：仓库内闭环。挂 9/41。
- 判别：档案提到「当前时间怎么取」时，把它当主要风险。
- 挂：django-11848 隐藏测试只 mock `utcnow`，用 `now(utc)` 会 TypeError。
- 过：fluentd-4598 完全不依赖环境。

**7. 诱人的低成本错误路线**
- 挂侧：改共享入口、通用构造器或运行时间隔看似最小，却波及既有行为。挂 14/42，是最常见的挂因。
- 过侧：自然改法局部，没有捷径。挂 4/19。
- 判别：先问「最省事的改法会不会动到别的模式分支」。
- 挂：django-12406 只在 `__init__` 加条件，误伤其他 widget。正确做法要区分 blank、required 和 RadioSelect。
- 过：django-12304 的陷阱（类体写入会变成成员）已被档案点明，避开即可。

## 三、判断者常犯的误判

### A. 误报：把能做对的题判成会挂

**被什么吓到：**
- 根因要推断，或需要实测复现。
- 隐藏测试断言未知、需精确匹配快照。
- 题面有两种写法，或并发难复现。
- 涉及多个 port 或多层，看起来牵连很大。

**判断步骤：**
1. 数改动面。单文件、单方法、约 10 行以内，就不要判高。
2. 找仓库内同类先例。有先例，诊断难也不等于实现难。
   - 挂 0.7 误报：lombok-3326 只改一个 handler，有 #3097 前例。
   - 挂 0.6 误报：vue-11739 有 #11188 模板。
3. 看档案是否已给行号级根因。有的话，并发、栈深这类难复现不再是风险。
   - fluentd-4030 加 nil 判断即可。micropython-13569 只调预留量。
4. 看测试实际跑的范围和断言强度。micropython-12158 只在 unix port 跑，只检查非零和不同，不必改 6 个 port。
5. 题面多种写法并存时，取仓库已有的最自然写法。rubocop-13687 取 wrap。
6. 快照要逐字符匹配时，看档案是否给了现成写法。有就是惯例写法，lombok-3674 的 null 转型就是如此。
7. 根因已定位且改动很小时，不要因「看着难」就给 0.5 以上。immutable-js-2005 被 DS 判 0.7，实际 14 家只有 2 家没做对。

**对照：** immutable-js-2006 档案已锁定 `NaN|0`，DS 仍判 0.45，14 家 0/14 挂。反例是 gson-2479 判 0.3，14 家 11/14 挂，差别在后者有兄弟路径和子类泛型。

### B. 漏报：把会挂的题判成能做对

**被什么骗了：**
- 「改动只有一行」。
- 「档案已点明并列处，智能体会照做」。
- 「题面已给修法」。
- 「档案说最小修法只改一处」。

**判断步骤：**
1. **题面只提一侧，就查另一侧。** 检查读写、序列化和反序列化是否对称。
   - 挂：gson-1100 题面只讲序列化 NPE，`read()` 也要支持 null，Sonnet 判 0.2。
2. **档案列出并列实现，就查它有没有现有测试。** 没有测试覆盖的并列处，隐藏测试往往恰在那里。
   - 挂：gson-2061 一行改动但漏 JsonTreeReader，DS 和 GLM 判 0.2 到 0.32，实际 7/14 挂。
   - 挂：phpspreadsheet-3469 同一脏字符串有第二个读取点，Sonnet 判 0.4。
3. **看档案是否出现「多条可行修法」。** 有就上调，因为 DS 常选错层。
4. **看档案的边界条目是否含「非法或无端口」。** 有就当显式用例。
5. **看是否有 mock 或接口二选一。** 只有一种取法能过时，不要因改动小而压低。
6. **看是否要区分多个相近条件。** 如 blank、required、widget 类型，近似条件会误伤。
7. **现有测试与题面冲突、修复方向无法从题面推知，就判高。** rubocop-13560 被 DS 判 0.22，14 家全挂。
8. **看是否缺依赖或需新接口。** carbon-2813 缺 psr/clock 依赖，要显式实现 `now()`，GLM 判 0.25，11/14 挂。fpm-1829 的 `fix_provides` 完全不校验运算符，校验完整性难，GLM 判 0.35，14/14 挂。

**对照：** gson-2061 改一行却挂 7/14；fpm-1850 改几行却稳过。区别是前者有未被测试覆盖的并列实现，后者没有。

## 四、操作顺序

1. 先从 0.1 到 0.2 起步。
2. 逐条核对第二节的 7 个挂侧信号，每出现一个明确信号再上调。
3. 信号只能来自档案里的具体事实，如并列处、第二读取点、冲突断言、多条修法、mock 约束。「看起来难」不算信号。
4. 有两个以上独立挂侧信号，才判到 0.5 以上。
