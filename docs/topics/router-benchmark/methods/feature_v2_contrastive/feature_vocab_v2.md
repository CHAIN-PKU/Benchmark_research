# DS 核心特征 v2（对照阅卷归纳，2026-11-16 13:4x）

来源：旧题 48 道 DS 挂题，每道配 2 道同仓库 DS 做对的题对照阅读（Sonnet），只保留「挂的那道有、做对的没有」且动手前可见的特征。按仓库分两半各自归纳，两半得到的主题基本一致，合并为下面 13 条。
判断依据：题面 + 动手前在仓库里查到的线索。每条只答 0/1。

V01 没有明确判据：题面没有报错栈、没有可复现输入、也没有精确的期望输出，只描述想要的行为或需求。
V02 一个例子、一类问题：题面只给一个例子或一种形态，而相关逻辑是通用的，存在题面没提的并列变体（其他关键字、节点类型、参数取值、平台、输入格式）。
V03 并列实现没点名：仓库里有需要同样改动的并列实现、成对方法或多个调用点（读与写、兄弟子类、同族函数），题面没提到它们。
V04 症状处不是根因处：症状出现的位置和可能的根因不在同一层或同一文件，存在两个以上看似合理的修复落点。
V05 题面给的修法可能是表层的：题面附带了修法建议、补丁或指向某一行，但这一处更像症状层，或与项目已有意图不一致。
V06 依赖题面外的规范或惯例：正确行为取决于外部标准、参考实现或项目隐含惯例，题面没把细节写出来。
V07 输出细节没说死：维护者测试很可能逐字检查输出（格式、精度、文案、退出码、顺序），而题面没把这些写清楚。
V08 新增能力要跨层改：要新增选项、类型或接口，并且需要穿过多层或在多处注册。
V09 需要新的状态或结构：修复要引入新的状态、作用域、遍历中的累积或改控制流，而不是改一个条件或一个值。
V10 现有测试与要求冲突：仓库现有测试断言了题面想改掉的行为。
V11 现有测试兜不住：现有测试不覆盖题面相关的边界或路径，只照题面例子自测很容易自以为通过。
V12（保护）有明确改点或模板：题面直接指出要改的位置和改法，或仓库里有可照抄的同类实现。
V13（保护）报错即根因：题面有清晰的报错栈，出错点就是要改的地方，改一处即可。
