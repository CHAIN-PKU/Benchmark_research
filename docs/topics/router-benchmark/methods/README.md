# 候选方法实验记录

## 方法 1：叠加校准（2026-11-15 14:0x）——负结果
数据：186 道训练题（宽松口径挂 46 道）；随机分层 5 折 × 10 次，及按仓库分组 5 折。叠加器用内层交叉验证的单项分数训练，避免泄漏。脚本 stack_exp.py。

| 方法 | 随机 AUC | 换仓库 AUC | Brier |
|---|---|---|---|
| 大模型事前判断（Sonnet 读仓库，事前标签那组的 p_fail） | 0.677 | 0.677 | 0.176 |
| 相似题 kNN（题面 TF-IDF，k=10） | 0.50 | 0.51 | 0.205 |
| 同仓库历史挂率 | 0.45 | 0.45 | 0.21 |
| 简单特征（题面长度、提到的文件数、代码块数） | 0.45 | 0.47 | 0.195 |
| 事前知识点标签 → 回归 | 0.51 | 0.52 | 0.192 |
| **理想知识点标签（看答案）→ 回归，上限参照** | 0.67 | 0.68 | 0.170 |
| 叠加：大模型 + kNN + 事前知识点 + 简单特征 | 0.64 | 0.66 | 0.180 |
| 叠加：大模型 + kNN | 0.65 | 0.67 | 0.180 |
（全猜均值的 Brier = 0.186）

读法：
1. 所有「便宜」的历史信息基线都接近瞎猜：相似题、仓库挂率、简单特征、事前知识点都 ≈0.5。在 186 道的规模上，**历史标签本身几乎不携带可迁移信息**；能预测的只有「读这道题本身」。
2. 大模型事前判断（0.68）≈ 用标准答案打出的理想知识点（0.67~0.68）。即强模型读仓库，已经达到「知道这题真正需要什么」的水平。
3. 叠加不加分，略降：其余信号是噪声，回归把它们加进来反而稀释。
4. 推论：方法 2（检索相似历史题给预测员）预期收益很低（kNN 本身 0.50），降低优先级；更值得试的是方法 3（结构化取证：逼预测员列出并列位置/边界写法）和方法 5（多次采样分歧 → 选择性预测）。

## 机理实验：查证 vs 判断拆分（2026-11-15 17:0x）
问题（crc）：同样读仓库，为什么 Sonnet 比 DS/GLM 更会预测？
做法：取各预测员在 84 道上已产出的「证据」字段（≤3 条，文件:行号 / 题面原句），去掉它们自己的概率和风险分；只把「题面 + 证据」交给 Sonnet 做判断（不读仓库、不调工具、单轮）。脚本 judge_swap/judge_swap.py。

| 组合 | 题数（挂） | AUC |
|---|---|---|
| Sonnet 查 + Sonnet 判（原） | 81（15） | 0.68 |
| Sonnet 查 + Sonnet 只看证据重判 | 81（15） | 0.69 |
| DS 查 + DS 判（原） | 81（15） | 0.57 |
| **DS 查 + Sonnet 判** | 81（15） | **0.67** |
| GLM 查 + GLM 判（原） | 72（14） | 0.52 |
| **GLM 查 + Sonnet 判** | 72（14） | **0.66** |

DS 证据换 Sonnet 判断：+0.09（成对重抽样 −0.03~0.24，93% 为正）。
读法：
1. 弱模型查到的证据，交给强模型判断，准度几乎追平强模型自己查（0.66~0.67 vs 0.68）。**弱模型输在「把证据变成难度判断」，不在查证**。
2. 案例（redis-11631、immutable-js-2005、rubocop-13362、jekyll-8761）：DS 与 Sonnet 找到同一行代码、同一缺漏测试；Sonnet 据「定位准、改动小」判容易，DS 反判为难。
3. 方法含义：「便宜模型查证 + 强模型短判断」成本远低于强模型全程读仓库，准度接近——作为方法候选，需在前瞻测试集复核。
4. 局限：证据只有 ≤3 条摘要（判断者看到的信息比原预测员少）；样本小；反方向（Sonnet 查 + DS 判）待 DSH 用 DS 通道跑。
