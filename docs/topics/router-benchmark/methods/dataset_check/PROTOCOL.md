# 数据集确认协议（crc 01:34：训练集和测试集要能泛化、挂因相似；DSH 先跑，数据集确认 OK 后我再推进方法）

写于新题（rebench、前瞻、DeepSWE）DS 标签揭晓前；标准事先写定，揭晓后只按它判，不改。

## 要确认的三件事
1. **标签稳定**：新题上 DS 同一道题跑两遍的一致率 ≥ 85%（旧题 89%，挂的复现 83%）。口径：以「至少一次未通过」和「两遍都未通过」两种都报。
2. **训练集与测试集的挂因相似**：
   - 旧题 186 道（训练）：挂因按固定分类（err_taxo.py 的漏报类 A~G / 过判类 H~M）和坑类型（T1~T6 的失手率）；
   - 新题（测试）：同一套分类，同一个标注者（Sonnet），对 DS 挂的题逐个归因（事后，读真实隐藏测试）；
   - 判据：两边挂因类别占比的差异检验（卡方 / 精确检验）不显著（p > 0.1），并且主要挂因（题面没写明期望、被误导、并列另一侧）在新题里仍是前三。
3. **题型覆盖**：有区分度的三个题型（题面误导、期望没写明、现有测试冲突）在新题里各 ≥ 30 道（现状：新题 26/52/12，合并旧题 53/93/38）。
   - 现有测试冲突一类新题只有 12 道，不足；是否需要补由 crc 决定。

## 不通过时怎么办
- 1 不过：说明 DS 在新题上成败噪声大 → 先补跑多遍取软标签，再谈方法；
- 2 不过：说明旧题学到的挂因不适用新题 → 论文结论写成「挂因不跨数据集迁移」的负结果，不再往提示词里加东西；
- 3 不过：按题型主动扩数据（DSH 跑），不再调方法。

## 通过之后
才推进：按冻结的臂（清单 3 条、档案 + Sonnet 校准、规则打分、针对执行者预测等）在新题上一次性揭晓。
