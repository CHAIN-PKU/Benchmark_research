# 闭环：规则 → 打分 → 判错 → 改规则（2026-11-16 晚，crc 19:54「不要换成其他模型的数据，对着 DS 成败和判断者对错，不断迭代方法论」）

只用 DS 跑题成败 + 判断者输出。流程（rule_loop.py）：
1. 起始规则 = 该折挂/过成对对比得到的 7~8 条区分清单（只来自该折）；
2. Haiku 对每道训练题逐条打 0~1（像挂侧/过侧）；L2 逻辑回归拟合权重；
3. 5 折交叉验证找出判错的训练题（漏报 6 + 误报 6）；Sonnet 看这些题和事后结果，改规则（新增 ≤3、删除 ≤2）；
4. 3 轮后，留出的另一折只评一次（最终规则 + 起始规则对照）。两个方向各做一次：训练折 0→评折 1，训练折 1→评折 0。

## 迭代过程（训练折内交叉验证 AUC）
训练折 0（71 道，17 次挂）：0.711 → 0.725 → 0.744 → 0.697（第 3 轮过拟合）
训练折 1（86 道，23 次挂）：0.573 → 0.631 → 0.627 → 0.666
每轮 Sonnet 的归因（节选）：漏报多为需条件守卫、并列/对侧读取点漏改、改共享函数；误报多为有现成参照的机械局部修补；权重近零的规则（落点唯一、状态机、牵连多处）被反复删除。

## 读法
1. 迭代没有带来留出增益：最终 0.607 vs 起始 0.606；训练折内的上升（+0.03~0.09）全是对该折的拟合。
2. 规则打分器不优于不看历史的判断者，更不如 Sonnet；概率上与常数基线无显著差。
3. 方向间波动大（0.72 vs 0.49），样本（约 20 次挂/折）撑不起稳定结论。
4. 结论：单一执行者约 40 次挂的历史，学不出可泛化的显式规则；这是写入论文的负结果，也是「需要更多执行者和更多任务才能让历史起作用」的直接证据。
