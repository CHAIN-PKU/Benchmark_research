# 题面特征表 v1（只看题面就能判断有没有）

来源：对公开 14 家智能体在「总结集」186 道题上的 125 个失败做阅卷（Sonnet），把「做之前能看到的线索」归纳成下面 12 条。前瞻集 114 道未参与总结。
用途：只根据题面（不看代码、不看答案）给每道题打 0/1。

C01 全称范围：题面用「所有 / 每个 / 各种 / 这一类都 / both / all X」描述要支持或要修的对象，或说「内置的某类实现都有这个问题」。
C02 单例窄化：题面只举了一个具体例子（一个值、一个平台、一个修饰符、一个调用写法），而问题描述的是一类行为；或标题带限定词（如「on Windows」）。
C03 对齐外部规范：要求和某个参考实现、标准、协议或其他框架的行为一致（如 GNU 工具、RFC、PSR、React、某格式规范）。
C04 题面给了修法或位置猜测：作者建议「改这一行 / 在这里加判断 / 也许可以抛错」，或指明他认为的出错文件、函数。
C05 以报错/堆栈为主要证据：题面核心证据是一段异常栈、panic、报错文字，而不是对期望行为的描述。
C06 特定特例：问题只出在某个特定属性、字段、值（如 0、空串、false、undefined、某个特定名字）上，其他同类正常。
C07 边界措辞：题面涉及空、零、单个 vs 多个、首尾、溢出、精度、超时到期等边界条件。
C08 输出形态没说死：要求「应该报错 / 应该提示 / 应该支持」，但没写清具体的报错文字、退出码、输出格式或顺序。
C09 优先级或顺序语义：涉及多个选项谁覆盖谁、执行或输出顺序、结果依赖属性或参数顺序。
C10 深层机制：涉及状态与生命周期、错误恢复、并发、缓存或增量更新、编译器/解释器内部、渲染调度等不在表层的机制。
C11 多种可接受做法：题面列出两种以上可能的修法或期望，没有说哪一种是对的。
C12 新增能力：要求新增一个选项、配置、类型支持或接口（不是修已有行为的 bug）。
