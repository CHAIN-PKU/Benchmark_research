# 坑级历史：DS 在哪类改动上容易挂（2026-11-16 晚）

起因：crc 17:52「给历史信息的重点应该是总结 DS 在哪些任务上改哪些地方容易挂，核心错题归因才是根本」。
配合 ch5_found 的发现：档案 97% 写到了真实失败点，但判断者掂量不出。

## 流程（pit.py）
1. extract（Haiku，157 次）：每道旧题档案抽 3~6 个坑，分 6 类：T1 边界/隐含行为、T2 并列与牵连、T3 约定与形状、T4 题面误导、T5 定位与规模、T6 其他。共 772 个坑。
2. label（Haiku，38 次）：DS 挂且有阅卷归因的题，判哪个坑是真实失败点（37 道对上）；做对题的坑全记「躲过」。
3. table（Sonnet，10 次）：按仓库两折，每折每类坑：踩/躲计数 + 分界规律 + 踩/躲各 1 例。
4. judge：逐坑估概率再合成（给/不给另一折踩坑表）；以及「整体判 + 踩坑表」。各 157 次 Haiku。

## 踩坑表（两折各自独立总结，规律一致）
- 踩坑率：题面误导 T4 最高（8/36、8/43 ≈ 20%），边界 T1 约 7%，并列 T2 3%~11%，约定 T3 约 5%。
- 规律（两折独立得出，几乎相同）：**踩**——题面只给主路径，隐藏测试考「对称/镜像分支」或「题面没定的语义选择」（如 gson 只说 write 的 NPE、隐藏测试考 read 侧 null；时区、utcnow、非法输入是拒绝还是静默）；**躲**——边界在代码或题面里直接可见、可以按清单补全的（null/空/重复/嵌套等）。

## 结果（146 道有公开 14 家成绩，DS 挂 34）
| 做法 | 与 14 家难度相关 | 14 家 AUC | DS AUC |
|---|---|---|---|
| 档案 + Haiku（现有，整体判） | 0.465 | 0.689 | 0.634 |
| 逐坑判 · 不给历史 | 0.317 | 0.627 | 0.564 |
| 逐坑判 · 给踩坑表 | 0.403 | 0.663 | 0.624 |
| 整体判 + 踩坑表 | 0.435 | 0.682 | 0.624 |
| 纯历史：按坑类型查踩坑率（不调模型） | 0.181 | 0.597 | 0.583 |
| 档案 + Sonnet（现有最好） | 0.541 | 0.721 | 0.708 |

配对区间：踩坑表 − 不给（逐坑格式）相关 [−0.04, +0.21]、DS AUC [−0.02, +0.14]；整体判 + 踩坑表 − 整体判 相关 [−0.13, +0.07]。
坑内部：挂题里真实踩的坑被排第一的比例，不给历史 0.43、给踩坑表 0.57（随机 0.34，n=37）。

## 读法
1. 历史在「坑这一层」有用：给了踩坑表，判断者更能认出 DS 会踩哪个坑（0.43→0.57），逐坑格式下整题准度也回升（DS AUC +0.06）。这是目前历史信息最大的一次作用。
2. 但落到「整道题挂不挂」没有超过整体判：逐坑拆分本身损失大（−0.15 相关），踩坑表只补回一部分；直接加到整体判里也没增益。
3. 原因：每道题档案都列着几个「题面没点明的分支」型的坑，单坑踩坑率只有 5%~20%，历史上踩坑事件每折只有约 20 次——规律说得出来，但不足以把「挂」和「过」的题分开。
4. 对论文：第 4.4 节历史加工按「抽坑 → 归因打标签 → 踩坑表」写；第 5 章结论：查得到（97%）→ 坑级能认出（0.57）→ 整题掂量仍是瓶颈，需更多踩坑事件（多模型、多次运行）。
