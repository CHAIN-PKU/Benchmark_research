# 挂/过成对对比 → 区分清单（2026-11-16 晚）

起因：crc 18:19「不要只看挂的题，要和没挂的放在一起比，否则总结出的信息没挂的题也有，容易搞混」。
先验事实：挂 40 道与过 117 道的档案坑几乎一样（每题 4.9 个，类型比例相同，仅「题面误导」0.65 vs 0.46）——只看挂题的踩坑表分不开。

## 流程（contrast.py）
1. pairs：每折内给每道挂题配一道最像的过题（同仓库优先 37/40、坑类型构成最近、过题不重复用）。
2. diff（Sonnet，40 次）：并排读两份动手前档案 + 挂题阅卷，只找「动手前就能看出、A 是这样 B 是那样」的区别，≤3 条。
3. checklist（Sonnet，2 次）：每折把各对区别归纳成 7~8 条区分清单（问题 + 挂侧 + 过侧），只留多对反复出现的。
4. score（Haiku，157 次）：用另一折的清单逐条判「更像挂侧还是过侧」+ 整题 p_fail。

## 两折各自独立得出的清单（高度重合）
- 期望是否唯一明确、与现有测试不冲突（fold1 该条在另一折上 DS AUC 0.74，最强）
- 修复落点是否唯一，还是有多个看似合理的落点 / 题面点名位置与真实落点不符
- 题面只给一个例子、要自己推广到整类（并列写法、成对 API）
- 现有测试里有没有可对照的断言
- 题面有没有诱导捷径（现成补丁、平台字样、低成本但波及既有行为的改法）
- 修法是开放式设计（新接口、拒绝非法输入）还是补一个确定的点

## 结果（146 道，另一折清单）
| 做法 | 与 14 家难度相关 | 14 家 AUC | DS AUC |
|---|---|---|---|
| 档案 + Haiku（现有） | 0.465 | 0.689 | 0.634 |
| 区分清单 + Haiku（p_fail） | 0.475 | 0.691 | 0.624 |
| 区分清单 逐条平均 | 0.485 | 0.697 | 0.600 |
| 合并：档案 + Haiku ⊕ 清单逐条（秩平均） | 0.497 | 0.702 | 0.619 |
| 档案 + Sonnet（现有最好） | 0.541 | 0.721 | 0.708 |
相关差（对档案 + Haiku）：清单 [−0.09, +0.11]，合并 [−0.02, +0.09]。单条在另一折上 DS AUC 0.48~0.74。

## 读法
1. 成对对比给出了**可复现的区分要素**：两折独立归纳出几乎同一张清单，核心是「期望和落点是否唯一确定」——题面没定、落点不唯一、要从一例推广到一类时挂；有明确复现与期望、可对照现有断言、只补一个确定的点时过。这是论文第 5 章「要素」的主体。
2. 这些要素和 14 家公开难度相关 0.3~0.5，主要是「题本身难在哪」，不是 DS 特有。
3. 打包成提示给 Haiku，只小幅、非显著提升（+0.01~0.03）。下一步：Sonnet + 清单（157 次 Sonnet，需和 DSH 跑题错开额度）。

## 补：Sonnet 按清单判（11-16 19:10，156 次 Sonnet，1 道输出格式坏）
（result_sonnet.txt 里组名沿用「+Haiku」字样，实际判断者是 Sonnet。）
| 做法（145 道） | 与 14 家难度相关 | 14 家 AUC | DS AUC |
|---|---|---|---|
| 档案 + Sonnet（无清单） | 0.540 | 0.720 | 0.706 |
| 区分清单 + Sonnet | 0.526 | 0.715 | 0.643 |
差（清单 − 无清单，Sonnet）：相关 [−0.07, +0.04]，DS AUC [−0.11, −0.02]。
读法：强判断者拿到清单不更准，对 DS 反而变差——清单把它的注意力拉向「题难不难」的通用要素，丢掉了它自己整体判断里的部分信息。Haiku 从清单只得到很小帮助（0.47→0.48，与原判断合并 0.50，区间跨 0），Sonnet 也不能：历史凝练出的要素，强判断者本来就会。
