## 贯穿的三条发现
1. **查全 > 掂量技巧 > 历史条目**：最大的一次提升来自把仓库查全写成档案；之后各种历史用法都在 ±0.05 内。
2. **瓶颈在掂量**：档案 97% 写到了真实失败点；读懂代码的程度与判对与否几乎不相关（DSH 5.4 测验，−0.10~+0.18）；各预测者误判的主因都是「查到了没掂量对」。
4. **（11-16 晚更新）单个执行者的历史在排序上基本不增加信息**：闭环规则、画像曲线、技能表、奥卡姆清单都不超过不看历史的判断者；稳定的正收益只有一处——用训练折把判断者概率拟合成概率（Sonnet Brier 低于常数基线 0.021）。要证明历史能提排序，需多执行者与新题标签。
3. **历史的作用取决于判断者强弱**：对弱判断者能补一部分掂量；对强判断者，历史凝练出的多是它已有的通用难度知识，稳定的作用只在校准。历史量（每折约 70 题、约 20 次挂、单一执行者）是当前上限，多模型与新题标签到齐后重验。

## 借鉴：人类老师 / 认知诊断 / 知识追踪 / ExpeL（11-16 20:25，crc 要求纳入经验）
- 认知诊断（DINA / Q 矩阵）：题 × 技能的 Q 矩阵 + 学生掌握度（需多学生 × 多题矩阵联合估计）；预测 = 掌握度覆盖所需技能，留手滑 / 蒙对。2026 有工作把它用到 LLM 评测，跨榜单 AUC 约 0.77~0.81（arXiv 2603.14676、2604.12191；摘要级，引用前核原文）。
- 知识追踪：LLM 直接猜对错输给专用统计模型（DKT AUC 0.83 vs LLM；arXiv 2512.23036、2409.16490）；LLM 的价值是把文本变成技能 / 错因标签。
- ExpeL（arXiv 2308.10144）：从成功 / 失败对提炼经验条目，对共用清单做 ADD / UPVOTE / DOWNVOTE / EDIT，靠多任务投票留存；目标是让智能体做得更好，不是预测对错。
- 对照我们的三个 bug：① 让判断模型直接报概率（应由它出 Q 向量、统计模型出概率）；② 单执行者（DS ≈46 次挂）学不出掌握度（需要多执行者）；③ 没有按错因类别累积（一题一规则）。
- 对应改法：固定技能 / 陷阱表（只由题面与档案归纳、不看标签；out_tax/taxonomy.json，13 项）→ 每题 Q 向量 → 每个执行者 / 判断模型在训练折上拟合「Q → 失败概率」；多执行者到齐后做共享题目难度的 IRT。
