0结论先行

建议主线：方向 B（Predictive Judgment 的测量 + 归因 + 规则干预），方法部分降为「预测流程与基线」的一章，不作为主贡献；下游价值只做一个最小的、可在现有数据上完成的决策实验。

理由一句话：我们手上最可靠、最有新意的证据，不是「某个方法更准」（尚未证明），而是「不同模型看到的信息相近、识别的风险点相近，但给风险定分量的能力差异很大，且部分可被规则改变」——这是一个可测量、可归因、可干预的科学问题；但目前样本小、只有一个目标做题模型，结论必须写成「在 Coding Agent 场景中观察到」，不能写成通用智能能力。

1我们究竟在研究什么

研究对象的准确表述：在 Coding Agent 场景中，一个 Predictor 读取任务与仓库后，对「某个目标 Agent 能否通过隐藏测试」给出概率的能力。它由几个可拆开的子过程组成：查证（找到相关证据）→ 风险识别（列出可能导致失败的点）→ 风险权衡（判断这些风险是否足以导致失败、给多大分量）→ 概率校准（把判断换成合适的数值）。

不主张它是已被证明独立存在的通用智能能力；它与代码理解、任务难度识别、隐含约束理解、对目标模型习惯的理解、概率校准都可能相关，需要实验区分（第 5、6 节）。

4支柱 A 重审：预测方法

问题判断
技术创新是什么？「查证/判断」分离本身不新（检索+判断的流水线很常见）；可能的新意是成本结构：便宜模型查证、强模型短判断即可接近强模型全程读仓库（0.67 vs 0.68）。这是工程价值，不是准度突破。
分工有价值吗？作为测量工具价值很大（让我们能隔离「判断」）；作为方法，只在成本上有价值，需报成本—准度曲线。
历史经验有独立增益吗？机械历史（相似题挂率）无效；读历史记录、习惯卡 + 对照例子已在新题冻结，待揭晓。
多次聚合与选择性预测？重复性良好（DS 三次标准差≈0.05）；是否能形成「只在有把握时预测」的覆盖率—准度曲线，待揭晓。
若不超过强模型直接判断？方法章节定位为「预测流程、基线与消融」，主贡献转向测量与归因；不再继续堆复杂方法。

5支柱 B 重审：基准与归因

核心现象

多个模型拿到同一份证据，列出的风险点相近；但它们对「这些风险是否足以导致失败」的权衡差异很大，并且这种差异在事后判卷中同样出现。

各解释的证据状态

解释当前证据判断
风险识别 vs 风险权衡的差异风险点相近；风险分量区分力 0.73 vs 0.54支持（C 级）
代码理解能力不足尚无直接测试假设，需「理解题」实验
隐含约束理解不足失败归因显示 DS 做题时常照题面字面做；但这描述的是「做题者」，不等于「预测员」假设
不理解目标模型习惯习惯卡 / 读历史两组已冻结待揭晓

6Benchmark 的价值与效度

要回答的问题回答 / 需要的证据
测量了什么在固定证据或固定仓库访问下，Predictor 对目标 Agent 成败的排序与校准能力（AUC / Brier / Log Loss / 校准曲线）。
为什么值得单独研究执行前的判断是 Agent 规划、派活、执行前检查的前提；现有 Coding Benchmark 只测「能不能做」，不测「能不能预判」。
与普通 Coding Benchmark 的区别目标变量是「另一个 Agent 的成败」，答案来自真实执行；同一道题可对不同目标模型给不同答案。
构念效度同证据换判断者、证据互换，已能把「判断」与「查证」分开（C 级）。
区分效度（不是代码理解/难度识别的代理）未证。需要：①理解题得分与判断得分的相关；②「题目绝对难度」与「对特定目标模型的成败」的分离——要多目标模型：同一题对不同目标模型答案不同，只会识别难度的 Predictor 会失分。
外部效度判卷与事前判断强弱顺序一致（B 级）；与真实决策的关联 未证。
跨实验室可比协议已固定：快照无历史、禁网、空 HOME、固定提示（sha256）、先预测后运行、放行闸门、多次重复；需发布任务集、提示、运行器和标签。
不回避的问题：如果高分模型在真实 Agent 系统中没有做出更好的决策，这个基准的意义就只剩「刻画一种判断差异」，实际意义有限。所以论文必须包含一个下游决策实验（第 10 节实验三），哪怕是最小版本；若结果为负，也如实报告并据此收窄结论。

10最值得做的三个实验（按优先级）

实验一（P0）：前瞻、多目标模型验证
做法：在已冻结的 123 道 + SWE-rebench 100 道上揭晓 DS 结果；同一批题再加 1–2 个目标做题模型（建议 Haiku 5.5、GLM Flash，便宜、能力不同）；各 Predictor 对每个目标模型分别预测（先冻结）。
回答：差异是否稳定、能否跨目标模型（区分「识别难度」与「识别特定模型的能力边界」）、跨仓库（按仓库重采样）、校准如何。
图表：Predictor × 目标模型热力图；校准曲线；按仓库区间。
成本：主要在目标模型执行（需额度）；预测员调用中等。
DS 部分进行中 多目标模型未开展
实验二（P0）：风险权衡的归因与干预复核
做法：固定同一份证据，五个判断者 × {无规则, 同一份规则, 强模型示范}；加「代码理解题」（从标准答案构造：这个并列函数要不要改？这个边界会被测吗？）；在开发集与新题上各做一次。
回答：风险识别相近、权衡不同是否稳定；规则改善是否可复现、对谁有效；与代码理解的相关程度（区分效度）。
成本：只判断不读仓库，低。
部分完成（Haiku 三组）
实验三（P1）：预算受限的评测调度（最小下游决策实验）
做法：给定任务池与「只能真跑 k 道」的预算，用不同策略选题（随机 / 简单规则 / 历史表现 / 强模型直接判断 / 我们的流程），目标是用最少执行估出目标模型的整体通过率、或找出它会挂的题。用已揭晓的数据离线模拟，无需新执行。
回答：预测分数高是否带来更好的决策（信息量、找出失败题的召回）。
未开展（数据揭晓后可离线完成）

后训练数据筛选：只保留为 Discussion 中的设想；如要做，最小实验是「用预测中间段题与随机题各做一轮小规模 RL，比较未见题提升」，但需要训练资源，不进入本文主结论。

11标题、摘要与引言

一句话定位
我们在真实仓库级编程任务上，前瞻地测量模型在执行前判断「另一个 Agent 能否成功」的能力，并发现模型间的差异主要来自风险权衡而非信息获取。
核心 Research Question
一个模型能否在行动之前判断另一个 Coding Agent 的能力边界？不同模型为什么存在判断差异？这种差异能否被理解和改善？

具体 RQ

  1. RQ1：在严格的先预测后运行协议下，不同模型的事前判断能力有多大差异？是否稳定、可跨目标模型与仓库？
  2. RQ2：差异来自查证、风险识别、风险权衡还是概率校准？
  3. RQ3：明确的权衡规则或强模型示范能否改善弱判断者？对谁有效？
  4. RQ4：事前判断能力是否与事后判卷一致，并能否在预算受限的评测调度中带来更好的决策？

最重要的科学发现（目前措辞，待新题复核）

在相同证据下，模型识别出的风险点相近，但对风险是否足以导致失败的权衡差异显著；该差异在事后判卷中同样出现；部分中等模型可通过明确权衡规则改善，最弱的模型则不能。

贡献

  • 主要：①Predictive Judgment 的任务定义与前瞻测量协议（任务集、冻结、放行、多次执行标签）；②多模型比较与逐层归因（查证/识别/权衡/校准）；③权衡规则干预的效果与边界。
  • 次要：预测流程与基线（含低成本查证+强判断）、事后判卷对照、预算受限调度的离线评估、失败归因数据集。

标题

英文：Seeing the Same Risks, Judging Them Differently: Measuring Predictive Judgment of Coding Agents Before Execution
中文：看到同样的风险，作出不同的判断：编程智能体执行前判断能力的测量与归因

英文 Abstract（草稿，数字待新题揭晓后替换）

Before a coding agent spends minutes to hours on a repository-level task, can another model tell whether it will succeed? We study this predictive judgment under a strictly prospective protocol: predictors read the issue and the pre-fix repository, their forecasts are frozen and hashed, and only then is the target agent executed against hidden tests. On real tasks from multilingual SWE-bench-style repositories and fresh 2026 tasks, cheap signals such as historical failure rates and similar-task voting perform near chance, while frontier models that inspect the repository reach AUROC around 0.7–0.8. Controlled experiments that swap evidence between predictors show that the gap between strong and weak predictors is not explained by what they retrieve: given identical evidence, models list nearly the same risks but differ sharply in how much weight they assign to them. The same ordering appears when models judge finished patches without running tests. Explicit weighting rules improve a mid-tier predictor but not the weakest one. We release the tasks, frozen predictions, and protocol, and discuss when predictive judgment can inform evaluation and agent decisions.

Introduction 叙事结构

  1. 现象：Agent 执行昂贵；人类工程师在动手前会判断「这活谁能干、会卡在哪」。模型能否做到？
  2. 空白：现有 Coding Benchmark 测执行；自我置信度研究测「对自己」、短任务；路由按文本特征。缺少仓库级、对他者、前瞻的测量。
  3. 我们做了什么：协议 + 多模型测量。
  4. 发现：便宜信号无效；强模型能预测；差异在权衡不在查证；判卷一致；规则对部分模型有效。
  5. 意义与边界：判断能力是 Agent 决策的组成部分，但本文只在编程场景、有限目标模型上证明。
