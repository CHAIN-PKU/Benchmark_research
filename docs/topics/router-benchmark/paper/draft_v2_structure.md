## 主线 2：核心特征与题面信息量对判断的影响（对比实验）
- 因子 A 特征凝练方式（同上）；因子 B 题面信息量（原题面 / 截断 / +仓库文档摘要 / +仓库可检索）；因子 C 历史信息用法（不给 / 相似题挂率 / 模型自读历史成败摘要）。
- 基线：先验、简单特征、kNN（相似题投票）、IRT/知识追踪（理想/事前知识点矩阵）、LLM 预测员三档。
- 已有结果：便宜基线≈0.5；读仓库的 LLM 0.68~0.80；失败知识清单在新题上不加分；叠加校准不加分。

## 主线 3：数据归因与能力泛化（价值所在）
已有机理证据：
1. 查证 vs 判断拆分：同一份证据，Sonnet 0.70、Opus 0.69、Haiku 0.60、DS 0.56、GLM 0.53；弱模型的证据交给 Sonnet 判 → 0.66~0.67。差在「判断」不在「查证」。
2. 判断方式：各模型列出的风险点几乎一样，差在给风险定分量——强模型随题调整，DS/Haiku 一刀切偏悲观，GLM 一刀切偏乐观（风险分量本身的 AUC：Sonnet 0.73，DS 0.54）。
3. 自我预测：DS 预测自己 AUC≈0.47 且系统性悲观（与已有文献报告的「普遍过度自信」方向相反）。
泛化验证（同一种「信息不全时判断方案好坏」的能力，在编程的其他场景是否同样拉开差距）：
- 判卷：题面 + 别人的补丁，不跑测试判能否通过（220 道，进行中）→ 对应 RL 奖励打分、多答案重排、代码审查。
- 自停止：智能体做题途中「我改对了吗、要不要再测」——用 DS 自己的最终补丁让它自评，对比外部判断者。
- 派活：同一题预测 DS/Sonnet/Opus 谁做得成（多执行模型到位后）。
- 需求落差干预：给做题模型一份仓库推断的落差清单，看成功率是否上升（60 道，进行中）。
核心论点：预测只是探针；它暴露的是模型「在信息不全时把证据换算成判断」的能力差异，这种能力在判卷、自停止、派活中同样决定成败。若各场景的模型排名一致，就是一条可迁移的能力维度。
