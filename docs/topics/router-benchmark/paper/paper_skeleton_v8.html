Chapter 1

引言

为什么这项能力值得单独测

1.1为什么需要事前判断›
A2A 时代主 Agent 给子 Agent 派活；改代码、动数据、花钱这类事做了收不回；会说「我没把握」比硬做更有价值。人类社会靠简历、面试、试用期做同样的事。
1.2现状缺口›
派活评测里编排模型派对率只有 7.5%~29.5%（DecisionBench），但没人直接测「动手前判断成败」这项能力本身。
1.3研究问题›
RQ1 能否可靠测量、各模型差多少；RQ2 为什么有差异；RQ3 能否用更好的方法和信息提升；RQ4 能否转化为决策收益。
1.4贡献›
① 一套可复现的事前预测实验设置与协议；② 一个把「题面与仓库、预测模型、历史跑题记录」三类信息组织起来的预测框架；③ Benchmark 结果与归因；④ 下游决策价值的初步证据。
希望读者记住：这是一项单独值得测、而现有模型普遍不擅长的能力。
Chapter 2

相关工作

我们和谁有交集、区别在哪

2.1模型路由与 Agent 派活›
关注选谁、质量与成本；我们只研究其中可单独测量的「成功概率预测」环节。
2.2模型自知与校准›
大模型普遍自信过头；训练可改善自我失败预测。
2.3题目难度与 Agent 成败预测›
Agent Psychometrics（留出题 0.84，但用了标准答案和测试，且需见过该 Agent）；运行中途预测（EarlyEval）；评估器（PredictaBoard）。
2.4题面不清与提问›
Ambig-SWE 等，解释为何「题面没说清」是失败主因之一。
定位：不做新路由器，测的是路由、派活、筛题背后共同依赖的那项能力。
Chapter 3

问题定义与实验设置

先讲清楚怎么考

3.1任务定义›
输入：题面 + 修复前仓库 + 目标 Agent 是谁；输出：它通过维护者隐藏测试的概率。禁止看标准答案、隐藏测试和任何 Agent 在这道题上的运行结果。
3.2题集与切分在跑/等揭晓›
旧题 232（总结历史、开发方法）；前瞻 123；SWE-rebench 2026-07 共 100 道（没人跑过的主测试集）。按时间和仓库切分，历史信息只能来自更早、不同仓库的题。
3.3目标 Agent（被预测者）在跑/等揭晓›
DS 为主，GLM、Sonnet、Haiku、Kimi 第二批；公开榜 14 家做免费多目标验证。
3.4预测模型（预测者）›
Opus、Sonnet、Haiku、DS、GLM；同一输入协议下比较。
3.5协议已有›
先锁预测（校验码、时间）再执行；逐题核对开跑时间；预注册干预；两种「挂」的口径；剔除环境错误和带提示的运行。
3.6指标›
AUROC、Brier、LogLoss、ECE、按仓库分组的置信区间、配对检验、每题成本与延迟。
结论目标：这把尺子可复现、防泄漏、能拉开模型差距。
Chapter 4 · 方法

预测框架：三类信息如何进入判断

题面与仓库 · 预测模型的智力 · 历史跑题信息

4.1框架总览›
把一次预测拆成「查证 → 判断」两段：查证者读仓库，按固定格式写成档案；判断者结合档案、目标 Agent 档案和历史信息给出概率。三类信息分别进入：题面与仓库进档案；预测模型的智力体现在查证者和判断者是谁；历史跑题信息进目标 Agent 档案和参照案例。
4.2信息一：题面与仓库（仓库档案）›
查证者在修复前快照里查至少 10 次，按 7 节写档案：题面要点、相关代码、并列与牵连、现有测试与约定、边界与隐含要求、改动规模、难点一句话。不看答案、不打分。每题约 35 秒、0.18 美元。
4.3信息二：预测模型的智力›
查证与判断可以用不同模型：强查证 + 便宜判断、便宜查证 + 强判断、一步直接判断。比较的是同一信息下谁更会「把证据变成概率」。
4.4信息三：历史跑题信息怎么处理（核心）›
分四步，每一步都有对照实验：
① 清洗原始记录：每次运行的成败、两次是否一致、操作轨迹、补丁。剔除环境错误和带提示的运行；只用冻结前、与测试集不重叠的题。
② 归因（阅卷老师法）：挂题对照标准修复、测试、Agent 的补丁和轨迹，写三层原因：挂在哪、过程上错在哪、动手前能不能看出来；过题写「为什么没难住它」；再把挂题和同仓库做对的题成对对照，只留能分开两边的东西。
③ 四种提炼形式：a 整体先验：通过率，按语言分层，样本少于 15 道并入「其他」；b 经验卡：做事习惯 + 致命条件，每条都配「什么情况下不致命」；c 题面特征：只看题面就能判断的 12~13 条；d 完整案例：与新题同格式的档案 + 标准修复改了哪里 + Agent 实际做了什么 + 教训，挂过成对。
④ 使用方式：检索（按仓库或话题 / 按难点相似 / 随机）→ 注入判断（作为先验、规则或参照比较）。
4.5历史信息的处理结论（目前）在跑/等揭晓›
按仓库或话题检索的历史在 14 家上都约等于瞎猜；特征打分无效；整体先验主要管校准；完整案例增益小（+0.02，不显著）；经验卡在新题上预注册，待揭晓。
4.6要比较的方法族›
统计基线（历史通过率、仓库挂率、相似题、题面特征）；强基线（题目难度 + 模型整体能力）；直接判断；两阶段（3 条线索 → 判断）；档案法；档案 + 历史；针对执行者的预测；不同成本档。
这一章要让读者看懂：我们的预测由哪三类信息构成、每类怎么处理，尤其历史跑题记录是怎么从原始记录变成判断能用的信息的。
Chapter 5 · 主线 A

谁判得准

Benchmark 主结果

5.1便宜基线都接近瞎猜已有›
仓库历史、相似题、只看题面特征 0.45~0.57；在 14 家公开 AI 上同样成立。
5.2模型差距已有在跑/等揭晓›
Sonnet、Opus 读仓库 0.68~0.80；Haiku、DS、GLM 接近瞎猜；DS 判断自己 0.47。
5.3会做 ≠ 会判已有›
DS 做题约 75~80% 能做对，判断却接近瞎猜；判卷（只看补丁）排序与事前预测一致（Opus 0.81 > Sonnet 0.74 > …）。
5.4上限参照已有›
别家在同题上的成绩能到 0.91，说明失败主要源于题本身难；事前方法无法拿到，只作参照。
希望得到：① 判断力能被测出且差距大；② 执行能力和预测能力是两回事。
Chapter 6

为什么有差异：归因

把一次预测错在哪拆开来量

6.1看见 vs 掂量已有在跑/等揭晓›
同一份线索交给五家，列出的风险几乎一样，掂量轻重的准度差很多；弱模型查的线索交给强模型判，准度追上来。
6.2错误拆成四段在跑/等揭晓›
查：真正挂点有没有被档案查到；读：查到了有没有读懂（代码理解测验）；掂量：同一档案换判断者、逐节删档案；尺度：整体偏乐观或偏悲观。
6.3什么信息决定准度已有›
删节实验：没有哪一节单独决定准度，「现有测试与约定」「边界与隐含要求」影响最大，靠的是几类信息合在一起。
6.4失败来自哪里已有›
大部分是题本身难（各家共享），模型特有短板难以从题面看出；「题面没说清」比「题型」更能解释失败。
希望得到：差距在「把证据变成轻重判断」，而不在「找不找得到风险」。
Chapter 7 · 主线 B

怎么判得更准：方法比较

同样预算下谁更准、更省

7.1查全 vs 压缩已有›
档案比 3 条线索显著更准（+0.17~0.19）。
7.2对强基线已有在跑/等揭晓›
档案 + Sonnet 优于「Sonnet 直接读仓库判」（相关度 0.54 对 0.45，区间刚好跨 0）；档案 + Haiku 持平。新题预注册已冻结。
7.3历史信息的增益在跑/等揭晓›
整体先验、经验卡、完整案例各自带来多少增益（预注册 60 道 + 旧题 146 道）。
7.4掂量能否被教在跑/等揭晓›
具体规则、通用清单、反写规则（预注册 77 道 × 4 个判断者）。
7.5针对执行者在跑/等揭晓›
同一道题告诉判断者是哪个执行者，能否给出不同且更准的概率；是否超出「题目难度 + 模型整体能力」。
7.6成本与负结果已有›
查证每题约 35 秒、0.18 美元，判断可交给便宜模型；特征打分、取平均、粗历史、一行案例都不行。
希望得到：同样预算下「查全成档案再判断」更准；判断可交给便宜模型；历史信息的作用有明确边界。
Chapter 8

有什么用：下游决策价值

更好的预测能否变成更好的决策

8.1Agent 派活 / Routing还没做›
离线反事实（公开榜 14 家有每题花费；rebench 多模型齐后）＋ 小规模端到端。
8.2题目筛选已有›
按预测挑 50 道排出的名次一致度 0.80 vs 随机 0.66（公开榜模拟）。
8.3训练数据筛选已有›
可学缺口命中 17% vs 13%（弱证据）。
8.4省时间已有›
预测约 20 秒~1 分钟 vs 真跑 10~30 分钟。
希望得到：更好的预测能转化成更好的派活和更省的评测；可路由空间小就如实说。
Chapter 9

讨论与局限

不说过头的话

9.1认出的多是「题难」›
模型特有短板仍难预测。
9.2自知能力弱›
模型估自己很弱，自知能力是开放问题。
9.3范围与污染›
只覆盖代码任务；公开题有记忆污染风险，新题集用于主结论。
9.4未来工作›
训练闭环、RSI、Foresight-aware Agent Manager、动态多轮路由。
