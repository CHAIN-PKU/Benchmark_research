01 / 引言

为什么要在动手之前判断

人类社会不会让所有人把一件事都做一遍再挑最好的。我们靠简历、面试、试用期，在动手前估出谁能做成。

A2A 协作主 Agent 给子 Agent 派活
+
不可逆操作改代码、动数据、花钱
+
知道自己不行没把握就停下或转交
→
都需要动手前的判断力

1.2 · 现状缺口

派活派对率只有 7.5%~29.5%

DecisionBench 显示编排模型派活能力很弱，但没有人直接测「动手前判断成败」这项能力本身。

1.3 · 研究问题

能否测量？为何不同？能否提升？有何价值？

RQ1 能否可靠测量、各模型差多少；RQ2 为什么有差异；RQ3 能否用更好的方法和信息提升；RQ4 能否转化为决策收益。

贡献：① 一套可复现的事前预测实验设置与协议；② 把题面与仓库、预测模型、历史跑题记录三类信息组织起来的预测框架；③ Benchmark 结果与归因；④ 下游决策价值的初步证据。

03 / 问题定义与实验设置

先讲清楚
怎么考

先锁预测再执行，逐题核对开跑时间，防止任何结果泄漏到预测里。

3.1

任务定义

输入题面 + 修复前仓库 + 目标 Agent 是谁；输出它通过隐藏测试的概率。禁止看答案、测试和任何运行结果。

3.2

题集与切分

旧题 232（总结历史、开发方法）；前瞻 123；SWE-rebench 2026-07 共 100 道（主测试集）。按时间和仓库切分。

3.3

被预测者

DS 为主；GLM、Sonnet、Haiku、Kimi 第二批；公开榜 14 家做免费多目标验证。

3.4

预测者

Opus、Sonnet、Haiku、DS、GLM，同一输入协议下比较。

3.5

协议与指标

校验码、时间戳、预注册；AUROC、Brier、LogLoss、ECE、分组置信区间、成本与延迟。

结论目标

这把尺子可复现、防泄漏、能拉开模型差距。

04 / 预测框架（方法）

三类信息
如何进入判断

把一次预测拆成「查证 → 判断」：查证者读仓库写成档案；判断者结合档案、目标 Agent 档案和历史信息给出概率。

信息一题面与仓库 → 仓库档案
+
信息二预测模型的智力
+
信息三历史跑题信息
→
输出成功概率 + 理由

4.2 · 信息一 · 题面与仓库

7 节仓库档案

查证者在修复前快照里查至少 10 次：题面要点、相关代码、并列与牵连、现有测试与约定、边界与隐含要求、改动规模、难点一句话。不看答案、不打分；每题约 35 秒、0.18 美元。

4.3 · 信息二 · 预测模型的智力

查证者与判断者分开选

强查证 + 便宜判断、便宜查证 + 强判断、一步直接判断。比较同一信息下谁更会「把证据变成概率」。

4.4 · 信息三 · 历史跑题信息怎么处理（核心）——四步，每一步都有对照实验：

① 清洗

原始记录

每次运行的成败、两次是否一致、操作轨迹、补丁；剔除环境错误和带提示的运行；只用冻结前、与测试集不重叠的题。

② 归因

阅卷老师法

挂题对照标准修复、测试、Agent 的补丁和轨迹：挂在哪、过程错在哪、动手前能否看出；过题写为什么没难住它；挂题与同仓库做对的题成对对照。

③ 提炼

四种形式

a 整体先验（按语言分层，样本少于 15 道并入其他）；b 经验卡（习惯 + 致命条件，配不致命对照）；c 题面特征（12~13 条）；d 完整案例（同格式档案 + 真实结果，挂过成对）。

④ 使用

检索与注入

检索：按仓库或话题 / 按难点相似 / 随机；注入：作为先验、规则或参照比较。

4.5 · 历史信息目前的结论

粗检索没用 · 特征打分没用 · 整体先验管校准 · 完整案例帮助小（+0.02）· 经验卡待新题揭晓

按仓库/话题找历史 ≈ 瞎猜→压成条目丢信息→历史的作用有边界

4.6 · 要比较的方法族：统计基线、题目难度 + 模型整体能力强基线、直接判断、3 条线索两阶段、档案法、档案 + 历史、针对执行者、不同成本档。

06 / 归因

为什么
有差异

把一次预测错在哪拆开来量。

查

挂点有没有被查到

拿 DS 挂题的阅卷结论对照档案，看真正挂的那处有没有写进去。

读

查到了有没有读懂

代码理解测验（40 道 × 4 个判断者，DSH 在跑）。

掂量

轻重给错没有

同一档案换判断者；逐节删档案——没有哪一节单独决定准度，「现有测试与约定」「边界与隐含要求」影响最大。

尺度

整体偏乐观还是悲观

DS、Haiku 偏悲观，GLM 偏乐观，属于校准问题，单独量。

希望得到

差距在「把证据变成轻重判断」，而不在「找不找得到风险」

看见的风险几乎一样→弱模型的线索交给强模型判就追上来→差在掂量

08 / 下游决策价值

更好的预测
能否变成更好的决策

可路由空间小就如实说。

8.1 · Agent 派活 / Routing

等多模型跑完

公开榜 14 家有每题花费，可做离线反事实；rebench 多模型齐后做主证据和小规模端到端。

8.2 · 题目筛选

名次一致度 0.80 vs 0.66

按预测挑 50 道 vs 随机挑 50 道（公开榜模拟）。

8.3 · 训练数据筛选

可学缺口 17% vs 13%

弱证据。

8.4 · 省时间

约 20 秒~1 分钟 vs 10~30 分钟

预测 vs 真跑一道题。

09 / 讨论与局限

不说过头的话

9.1

认出的多是「题难」

模型特有短板仍难预测。

9.2

自知能力弱

模型估自己很弱，是开放问题。

9.3

范围与污染

只覆盖代码任务；公开题有记忆污染风险，新题集用于主结论。

9.4

未来工作

训练闭环、RSI、Foresight-aware Agent Manager、动态多轮路由。

10 / 全文希望得出的结论

四个核心结论

结论现状
① 事前预测可以超越「题目难度 + 模型整体能力」的简单基线对便宜基线已超越；对强基线待新题
② 执行能力排序与预测能力排序显著不同DS 已有初步证据，需多模型
③ 强预测器不是看到更多风险，而是更会掂量旧题证据最扎实
④ 预测差异能带来真实的派活收益等多模型数据

Benchmark first, routing as evidence, not as the paper's identity.
