# 回应 crc 研究备忘录（SciCustom 等），2026-11-15

作者：CRC 的 Claude Code（Opus 5.5）。依据：SciCustom 论文 HTML（摘要、第 1~3.2 节、表 1~2 逐字；其余为抓取摘要，待核 PDF）和 GitHub README；PRISM、SEGA 只读到摘要；MATE 页面打不开（未读，不引用）。我们自己的数字都来自本仓库已提交的运行结果。

## 一、读后感受
1. 备忘录说中了：我们的短板在后处理（标签、特征、划分），不在跑题。
2. 我们自己的数据已经出现了备忘录预警的症状：
   - 手写清单在新题上不加分：干净留出 90 道，清单 0.80 vs 通用提示 0.78（第十一、十二节）。
   - 分类体系改了 4 次（A~F 字母 → 三大类 → 行为领域 → 三层归因），每次都在看过结果之后改，属于「根据测试表现调整分类」。
   - 发生过一次泄漏：留出集里 13 道挂题参与过清单总结，事后才发现（已更正）。
   - 「任务需要什么」和「DS 怎么失败的」混在一个标签里（如「多入口」是任务需求，「照题面字面做」是失败过程）。
   - 归因只做过单个 LLM、一遍，没测可重复性。
3. SciCustom 值得借的是「纪律」而不是「算法」：固定一套单元词表 → 用同一个标注器统一打标签 → 用下游指标（排名相关）验证。它自己的验证也不算强：标注器 Macro F1 75.2%（还是模糊匹配），只有 10 个模型、没有置信区间，多数 Spearman 在 n=10 下不显著。所以不要照搬它的本体构建、专用标注器训练、代理子集。

## 二、我们现在的问题（按影响排序）
1. **没有简单基线**：我们直接上了 LLM 预测员，没先回答「最便宜的方法能到多少」。今天补算（干净留出 91 道，挂 19 道）：
   - 训练集仓库挂率当先验：AUC 0.35（反向，小样本仓库挂率不迁移）
   - 题面长度：0.61
   - Sonnet 读仓库（通用提示）：0.79
   → 读仓库的增益是真实的，但还没和「题面长度 + 改动规模估计 + 仓库」的小逻辑回归比。
2. **标签噪声没分级**：每题只跑 2 次，一过一挂约 12%；两种口径（至少挂一次 / 两次都挂）在混用；环境排除靠临时名单，没有 Gold/Silver/Uncertain/Invalid 分级。
3. **划分不够严**：只有随机留出；没有「换仓库」留出、跨题库（DeepSWE 刚开始）；置信区间按题重采样，没按仓库聚类重采样。留出集里仓库效应很强（django 0/11 挂、php-cs-fixer 3/4 挂），预测员可能部分是在认仓库。
4. **两类标签混用**：没有把「任务需求（事前可见）」和「失败机制（事后观察）」分成两个字段。
5. **指标单一**：只报 AUROC，没有 AUPRC、Brier、校准。
6. **污染**：公开题有记忆风险（通用组 104 道里 43 道自报想起上游修法）；三套题库 task id 零重叠（DSH 已查），commit/补丁级去重未做。

## 三、可借鉴的方法（标注来源与验证状态）
| 来源 | 原文已验证的 | 我们怎么用（未验证的假设） | 现在做吗 |
|---|---|---|---|
| SciCustom 单元词表 | 642 个单元，粒度由 LLM 判定 | 只在训练集上定一套 15~25 个「任务需求」词表，冻结后不改 | 做（简化版） |
| SciCustom 统一标注器 | 微调 8B 模型，F1 75~79% | 不训练；用固定提示的 LLM 只看事前信息打标签，两个模型各打一遍测一致性 | 做 |
| SciCustom 多模型投票 | 3 个模型排序取平均 | 两三个模型打标签，一致的当高置信 | 做 |
| SciCustom 代理子集 | 随机抽样会明显变差（只有图，无数字） | 有限预算下优先跑哪些题 | 以后（P3） |
| PRISM 候选标签集合 | 摘要级：噪声下优于基线 | 失败机制记「候选集合 + 证据 + 置信度」，不强行单一原因 | 做（只改记录格式，不上图算法） |
| SEGA 按可靠性加权 | 摘要级 | 消融：全部样本 vs 只用 Gold vs 加权 | 做（简单版） |
| MATE | 未读到原文 | 人工审核预算优先给：一过一挂的题、两个标注器不一致的、预测员高置信却错的 | 做（规则版，不引用 MATE） |

## 四、接下来怎么做
**DSH（跑题，数据是对的，继续）**
1. 只跑 DS：主批剩余 47 道 → DeepSWE 32 道 → 扩到 113 道；Pro 第三优先。
2. 每次运行打可靠性等级：Invalid（环境/评测错）、Uncertain（有争议，如测试没加载、超时）、Silver（自动评分可信）；Gold 由我抽审后升级。
3. 一过一挂的题和所有挂题补跑第 3 次，估计每题真实通过率（标签噪声）。
4. 导出元数据：仓库、base commit、题目创建时间，做 commit/补丁级去重和时间划分。

**我（后处理，P0 → P2）**
- P0 数据审计与划分（今天到明天）：每题一行审计表（等级、两次结果、环境标记、去重结果）；一次性冻结三种划分：随机留出、换仓库留出、跨题库（主批训 → DeepSWE 测）。
- P1 简单基线：B0 先验、B1 简单特征逻辑回归（题面长度、提到的文件数、语言/仓库、改动规模估计），对比 Sonnet 读仓库；指标 AUROC + AUPRC + Brier + 校准，按仓库聚类重采样出区间。
- P2 两套标签：任务需求标签（只用事前信息，冻结词表，两个模型打、测一致性）＋ 失败机制（事后，候选集合 + 证据 + 置信度，只用于训练集解释）。检验需求标签能不能在换仓库/跨题库上比 B1 多出增益。
- P3/P4（不确定性、主动选题、反哺训练）：暂不投入。

**停止/继续标准**：如果需求标签在换仓库和 DeepSWE 两种划分上都没有超过 B1（区间包含 0），就不再主张「能力分类体系有预测价值」，论文改成「强模型读仓库可事前预测，手工分类不加分」并报告这一负结果。
