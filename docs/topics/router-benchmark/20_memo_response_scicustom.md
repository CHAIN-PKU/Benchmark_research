## 二、我们现在的问题（按影响排序）
1. **没有简单基线**：我们直接上了 LLM 预测员，没先回答「最便宜的方法能到多少」。今天补算（干净留出 91 道，挂 19 道）：
   - 训练集仓库挂率当先验：AUC 0.35（反向，小样本仓库挂率不迁移）
   - 题面长度：0.61
   - Sonnet 读仓库（通用提示）：0.79
   → 读仓库的增益是真实的，但还没和「题面长度 + 改动规模估计 + 仓库」的小逻辑回归比。
2. **标签噪声没分级**：每题只跑 2 次，一过一挂约 12%；两种口径（至少挂一次 / 两次都挂）在混用；环境排除靠临时名单，没有 Gold/Silver/Uncertain/Invalid 分级。
3. **划分不够严**：只有随机留出；没有「换仓库」留出、跨题库（DeepSWE 刚开始）；置信区间按题重采样，没按仓库聚类重采样。留出集里仓库效应很强（django 0/11 挂、php-cs-fixer 3/4 挂），预测员可能部分是在认仓库。
4. **两类标签混用**：没有把「任务需求（事前可见）」和「失败机制（事后观察）」分成两个字段。
5. **指标单一**：只报 AUROC，没有 AUPRC、Brier、校准。
6. **污染**：公开题有记忆风险（通用组 104 道里 43 道自报想起上游修法）；三套题库 task id 零重叠（DSH 已查），commit/补丁级去重未做。

## 五、补充（crc 11:36 要求更详细）：跑完题之后的后处理流水线

### 5.1 从 SciCustom 学到的核心一点
SciCustom 是**先定义「题目需要什么知识」（与模型无关）**，给每道题（不分对错）都打上这些知识单元，最后才看每个模型在每个单元上的表现。
我们一直是**从 DS 的挂题出发**总结特征——这天然有偏：只看挂题，看不到「同样特征但 DS 做对了」的题；特征和 DS 绑死；看过结果再改分类。
→ 改成两步：先给**所有题**（过的和挂的）打「任务需求」标签，再算 DS 在每个标签上的挂率。

### 5.2 流水线（每批新跑完的题都过一遍）
1. **入库与清洗**（自动规则，不靠人判断）
   - 每次运行记：是否通过、该修好的测试过了几个（F2P 比例）、原来能过的测试坏了几个（P2P）、是否报错/超时/补丁为空/补丁没打上。
   - 自动判无效：原来能过的测试全挂（测试没加载，如 axios-5316）、模块找不到、构建失败 → Invalid，不进能力标签。
   - 标签不用 0/1，用**每题通过率**（2~3 次里过几次）；另记「差一点」（F2P ≥80% 但没全过）和「完全没做对」，这两类挂法不同。
   - 可靠性分级：Gold（≥2 次一致）、Silver（不一致）、Uncertain（次数不够/有争议）、Invalid。
2. **任务需求标签（事后标注器，看标准答案和测试）**
   - 只在训练集上，读标准答案 + 隐藏测试，回答「这道题本身需要什么」，例如：要改 ≥2 处并列代码、要处理边界/阈值语义、字符串格式/解析、精确报错文案、新增接口形状、跨文件、平台/协议条件、递归结构、对齐外部规范。
   - 粒度规则（借 SciCustom「像教科书章节名」）：一个标签至少出现在 5 道训练题里，且过的题和挂的题里都要有。
   - 词表自下而上长出来，合并同义后**冻结**（带 sha256），以后只能出新版本、新版本只在新跑的题上评估。
3. **事前标注器（只看题面 + 基线代码）**
   - 让模型预测同一套需求标签。和第 2 步的「正确答案」对比，得到**每个标签事前能被看出来的程度**（召回率）。
4. **挑核心特征**：一个标签算核心特征，必须同时满足——
   - 挂率提升显著：有它的题 DS 挂率明显高于没它的（置信区间不含 1）；
   - 有反例：带这个标签但 DS 过了的题也存在（说明不是死规则）；
   - 事前看得出：第 3 步召回率 ≥0.6；
   - 标得稳：两个模型各标一遍，一致性 κ ≥0.6，不稳的标签视为「浮动」，剔除。
5. **DS 能力画像**：DS 在每个需求标签上的挂率（用 Beta 先验平滑，少样本不乱跳），这就是「单模型的细粒度能力差异」。
6. **预测**：新题 → 事前标注器给出需求标签 → 简单逻辑回归（需求标签 + 题面长度 + 改动规模估计）→ 失败概率；和「简单特征基线」「Sonnet 整体读仓库」比，在随机、换仓库、DeepSWE 三种划分上看。
7. **失败机制标签（只做解释，不进预测）**：训练集挂题记「可能原因集合 + 证据 + 置信度」（借 PRISM），用来发现新的候选需求标签；两个标注器意见不一的、一过一挂的、预测员高置信却错的，优先人工复核。

### 5.3 让标签不再浮动的几个办法
- 标签对象从「挂的原因」换成「任务需求」：后者看标准答案就能定，和 DS 跑没跑、跑几次无关，天然稳定。
- 每个标签两个模型各标一遍，算一致性，不一致的标签直接剔除或合并。
- 冻结 + 版本号：改词表就是新版本，只能在之后新跑的题上评估，杜绝「看结果改分类」。
- 过的题也标：挂率提升必须拿过的题当对照，才知道特征是不是真的跟失败有关。
- 用通过率和「差一点」代替 0/1：一过一挂不再被当成噪声扔掉，而是信息。
