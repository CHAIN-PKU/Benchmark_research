# 与顾老师会议后的方向校准（2026-11-15 13:4x，CRC 的 Claude Code）

## 一、会议要点（我理解的）
1. 定位：做「**模型预测模型**」的基准——两个受控变量：被预测的做题模型、做预测的预测员模型。方法做得好是加分，做不好也能落成「模型缺乏事前判断能力」的发现；保底靠多维分析（家族相似性、思维链、归因）。
2. 边界：只做**同分布/近分布**（同一题库内随机 7:3），跨题库泛化不作主张。
3. 方法参照：教育测量的**知识追踪（KT）/ 项目反应理论（IRT）**，以及 kNN 相似题；新方法要超过它们才算加分。
4. 数据：每个子集约 100 道，「历史子集」和「评测子集」大小固定；必须有足够的挂题；找污染小、较新的题库；高质量子集单独再比一次。
5. 节奏：1 月初 ACL 冲刺（约 50 天），备选 1 月底 ICML、2 月 KDD 基准赛道、之后 MM/NeurIPS；每周三 14:00 线上汇报；经费和服务器走张明老师；正文写满、附录 4~5 页。

## 三、方向调整
### 1. 论文主线改成「预测员 × 做题模型」矩阵
- 主结果是一张表：行 = 做题模型（被预测者），列 = 预测员模型，格子 = 在固定评测子集上的 AUC/Brier。
- 现在只有 DS 一行；**至少要 3 行**才能谈「家族相似性」（同家族模型能否更好预测彼此）和「强模型是否更会预测」。

### 2. 挂题不够 → 两个杠杆一起用
- 换更难、更新的题：DeepSWE（2026 年新数据、DS 挂率约一半）提为**主题库**之一；Pro 对 DS 太容易，降为附录。
- **加较弱的做题模型**：同一批题让便宜/较弱的模型来做，挂率自然升高、样本更均衡；还能直接回答「预测难度随做题模型能力怎么变」。这比到处找新题库更省事。

### 3. 把「核心特征」工作重新定位为 KT/IRT 的「知识点矩阵」
- KT/IRT 预测「学生答新题」需要「题 → 知识点」的映射（Q 矩阵）。我们的任务需求词表正好就是 Q 矩阵：每道题需要哪些能力。
- 于是：事后标注（看答案）= 理想 Q 矩阵，事前标注（只看题面+代码）= 实际可用的 Q 矩阵；DS 在各知识点上的挂率 = 「掌握度」。
- 这样已有工作直接变成两个对照基线：「理想 Q 矩阵 + IRT」（上限）和「事前 Q 矩阵 + IRT」（实际），和 kNN、LLM 直接预测并列比较。我们已发现的「事后有信号、事前被稀释」就成了一条可量化的分析结论。

### 4. 基线清单（全部在同一历史/评测子集上）
| 编号 | 方法 | 用到的信息 |
|---|---|---|
| B0 | 历史挂率先验（全局/按仓库） | 历史标签 |
| B1 | 简单特征逻辑回归（题面长度、提及文件数、语言） | 题面 |
| B2 | kNN：历史里最相似的 k 道题的挂率（文本嵌入） | 题面 + 历史标签 |
| B3 | IRT/KT + 理想 Q 矩阵（上限参照） | 事后标签 |
| B4 | IRT/KT + 事前 Q 矩阵 | 题面 + 代码 |
| L1 | LLM 预测员，只看题面 | 题面 |
| L2 | LLM 预测员，读仓库 | 题面 + 代码 |
| L3 | LLM 预测员，读仓库 + 历史经验摘要 | + 历史 |
主比较：L2/L3 是否超过 B2/B4；不同预测员模型之间的差距。

### 5. 子集设计（按顾老师「每子集约 100 道」）
- 每个题库、每个做题模型：历史子集 100 道 + 评测子集 100 道（同分布随机划分，种子固定），评测子集里挂题目标 ≥30 道（不够就靠加弱模型提高挂率）。
- 高质量子集：只取两次结果一致（gold）的题再算一遍。
- 历史子集大小做成控制变量（25/50/100）画学习曲线。

## 四、50 天时间表（以 1 月初 ACL 为准）
