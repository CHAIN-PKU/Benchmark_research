# 给另一边两个机器人的说明（短版，可直接转发）

我们群里 Claude Code 和 DSH 能互相「@」、互相回话，靠的不是飞书的 @ 通知，而是：**两个机器人各自定时把群里全部消息拉下来看**。

## 为什么你们收不到对方
- 飞书的「消息事件推送」（im.message.receive_v1，有人发消息时飞书主动通知机器人）一般**不会推送其他机器人发的消息**（避免机器人互相触发死循环；以飞书官方文档为准）。所以只靠事件推送，机器人永远看不到另一个机器人说了什么。
- 在文本里写「@某某」只是文字，飞书不当成真的 @，也不发通知。

## 照这 5 步做
1. 两个机器人必须是**两个不同的飞书自建应用**（各有自己的 app_id）。
2. 每个应用开权限：发消息、**读取群里全部消息**（im:message.group_msg 一类），发布新版本让权限生效。
3. 两个机器人都**加进同一个群**。
4. 每个机器人写一个小程序，**每 1~3 分钟**调一次「拉群消息列表」接口：
   `GET https://open.feishu.cn/open-apis/im/v1/messages?container_id_type=chat&container_id=<群ID>&sort_type=ByCreateTimeDesc&page_size=50`
   记住上次看到的最后一条消息，只处理新的。
5. 约定规矩：每条消息开头带名字（如【A】【B】），文本里写 `@A` / `@B` 表示点名；**被点名的才回，没点名的不插话**；自己发的消息要跳过，避免自己回自己。

## 想要真的 @ 并让对方手机有提醒（可选）
- 发消息时文本里放 `<at user_id="ou_xxx"></at>`，其中 `ou_xxx` 要用**发消息这个应用自己查到的**对方 open_id（查群成员接口），不能拿另一个应用查到的 open_id 来用（会报 99992361）。
- 即便这样，对方机器人也还是要靠第 4 步的「拉消息」才能看到。

## 自查清单
- [ ] 是不是两个独立应用？
- [ ] 「读取群里全部消息」权限开了、新版本发布了？
- [ ] 两个机器人都在群里？
- [ ] 有没有在拉消息（而不是只等事件推送）？
- [ ] 是否跳过了自己发的消息、按点名规矩回复？
