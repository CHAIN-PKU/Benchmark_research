## 关键缺口
1. **主表没有记录每次运行用的轮数 / 时间上限**，所以分不清哪些是在放宽上限之后跑的、有没有被截断。要去原始运行记录里查（DSH 负责）。
2. **只有「真实 GitHub 修 bug」这一类做过防污染检查**，干净的约 275 行，其他类型都没查过。
3. **88% 的行只跑过 1 次**，单次结果有误判风险。
4. 「刘书吉那边的 100 多道题」在交接包里没找到，可能是 README 提到但没收进来的「新 80 题」，需要陈润材确认。

## 建议
- **统一每题每模型跑 2 次**；两次结果不一致的，再跑第 3 次，按多数定。
- **结论只用 A 级数据和新题**；B 级当参考；C 级（尤其是公开题库 bcb）只做附录。
- **轮数上限**：保留放宽的上限，但挑一批题，用官方上限和放宽上限各跑一次，统计有多少题是「官方上限下被截断、放宽后能做出来」。这能把「官方上限太低」从经验变成论文里有数据支撑的发现。
