# Router × Benchmark 课题脉络（Claude 部分，2026-11-13）

来源：`~/Router_Benchmark_Paper/` 交接包（00～03 号文档、`prereg/`、`paper/` 里的论文草稿 v2、一页纸导师摘要和计划 TODO）。数字都摘自这些文件，没有重算；实验盘点由 DSH 负责，见 `02_experiment_inventory.md`。

## 1 他们要做什么
- **问题**：在模型动手之前，只看「题面 + 历史评测结果」，能不能预测便宜模型（DS = deepseek-v4.1-flash，GLM = glm-5.3-flashx）做不做得出一道**新题**？能的话，就可以按「最便宜够用」来路由。
- **论文定位**：一篇测量研究，工作标题是 *Can Historical Benchmark Results Predict Which Model Solves a New Task? A Measurement Study of Scoring, Leakage, and the Predictability Ceiling*。负面结果也写，要求不拔高。
- **四个贡献**（草稿 v2）：
  - C1：一套无泄漏的评测协议。
  - C2：评分口径陷阱。综合分里混了 LLM 评委分，改成纯测试二元判定后，「来源先验」的 AUC 下降 0.08～0.11。
  - C3：判官并行泄漏陷阱。成片执行时判官 AUC 虚高到 0.71/0.785，隔离后降到 0.588。
  - C4：当前特征下预测信号很弱。

## 2 现在有哪些实验（摘要，详细清单见 DSH 的盘点）
- **开发集**：467 题，4 个模型（DS、GLM、Opus、Fable），评测主表 1525 行。标签已经用纯测试二元判定重算（`relabel_binary`）。按仓库分 5 折（split_v2）。
- **预测器**：全局常数、来源先验、叶子类型、题面长度逻辑回归、TF-IDF 最近邻、LLM 判官（Jev，以及 Haiku/Sonnet/Opus 级）。结果：AUC 约 0.51～0.65；长度相对来源先验的配对差 +0.06～+0.10，多数区间跨 0。
- **路由模拟**：固定模型、类型表、文本策略。省钱不成立：类型策略质量 87.2，低于固定用 Opus 的 88.6，还有 13～14 次严重选错。这些是旧口径数字，要重算。
- **标签噪声**：bax 来源 47 组重复运行里有 13 组（27.7%）结果不一致。
- **新题试点**：5 道 Multi-SWE-bench 风格题，4 道通过预检（surveyjs 作废）。godog 只到「最小闭环」，**evaluation_ready=0，一个模型都没跑**，$25 预算没动。

## 3 最急最重要要补的实验（按优先级，我的判断）
1. **打通评测基础设施**：godog 跑通完整官方 `run_evaluation`，适配层抽成通用脚本，再复制到 grommet、chezmoi、unplugin。不先打通，后面所有新题实验都做不了。
2. **扩充独立新题**：按 SWE-bench-Live / Multi-SWE-bench 的做法，从真实上游 issue/PR 出题，经过三关预检和多次运行剔除不稳定测试，审查测试点，补到 ≥20 道，最终目标约 60 道（要分辨 AUC 0.70 和 0.5，阳性、阴性各约需 20 道）。
3. **按预注册执行**：先冻结预测并记哈希，再让 DS/GLM 每题跑 2 次（≤$25），做二元评分，同时出分数—成本曲线。
4. **复核旧口径数字**：判官 AUC 和路由「91.1 分 / 成本为 Opus 的 71%」都是旧口径，要在二元标签下重算，否则论文里不能用。
5. **量化标签噪声**：在约 20 道题上各补 2 次运行，估计二元标签翻转率。

## 4 期望得到的结果
- **大概率是负面或测量型结论**：在严格评分和防泄漏的切分下，逐题预测信号很弱，稳定的信号只在来源/类型这一粗层面。
- **论文价值**：靠协议（C1）和两个方法学陷阱（C2、C3），而不是一个更强的路由器。
- **事前写好的「有增益」门槛**：在新题上，判官 AUC 的置信下界 > 0.55，且路由省钱比例的下界 > 10%。达不到就写「无增益 + 弱信号」。
- **停止条件**：标签可信之后任务级信息仍无稳定增益、又拿不到足够的独立新题，就转向「评测可靠性 / 泛化失效机制」研究。

## 5 baseline 和方法论
- **预测类 baseline**：全局失败率常数、来源先验、叶子类型、题面长度逻辑回归、TF-IDF kNN、LLM 判官。
- **路由类 baseline**：永远用便宜模型、永远用 Opus、类型表路由器。
- **要对比的相关工作**：RouterBench、LLMRouterBench、Routing Plateau。草稿注明要逐篇回查，还没核。
- **方法论**：
  - 标签：纯测试二元 resolved，即 F2P 全过且 P2P 全过。
  - 防泄漏：一题一调用；预测目标互不可见；先算哈希、后运行；按仓库分组交叉验证。
  - 预注册冻结：只能追加修正案，现有 A1～A11。
  - 指标分开报：单模型用 AUC + Brier + ECE；跨模型用 top-1 / regret（仅辅助）；成本决策用分数—成本曲线加严重错选数。区间用按仓库聚类的 bootstrap。
- **注意**：这不是「打败 baseline」型的论文。他们事先承诺「不宣称优于」，因为样本不足。如果想写成方法论文，就需要一个新的、事前写定的假设，再加约 60 道新题去验证。

## 6 我们的 skill 能怎么用（建议）
- **路线图八步**（`docs/roadmap.md`）：可以直接对照他们的新题流程，缺的正好是第 2 步题源、第 4 步判分器（测试点审查）、第 5 步难度标定（多次运行）。
- **BenchJack**：拿 V1–V8 审计他们的适配层和评测容器。他们已经做到 agent 看不到 test_patch、禁网，但「官方 Report 不拦被跳过的 P2P」这类问题正是 V6 判分逻辑缺口。
- **Inspect AI**（本机已装）：可以作为「数据集 + 解题器 + 判分器」的参照，用来对照适配层的设计。
- **research-wiki**：把四个贡献（C1～C4）、预注册假设、各口径数字记成论文页和论断页，防止口径混用。
