# 他们的做法 vs 官方评测做法：哪些是改进，哪些有害（2026-11-13，Claude）

「官方」指 SWE-bench、Multi-SWE-bench（多语言版的官方评测程序）这类权威基准的标准做法。依据：交接包的 01、03 号文档，预注册和修正案 A1～A11，以及 DSH 的盘点。

## 一、损害官方口径的（要改，或者在论文里说清楚、不能混用）

| # | 他们的做法 | 为什么有害 | 建议 |
|---|---|---|---|
| 1 | 旧分数用「综合分」，里面混了 LLM 评委（让大模型打分）的分 | 官方只认「测试全过才算通过」。混了评委分会让「来源先验」的效果虚高约 0.08～0.11 | 已改成纯测试二元判定（过 / 不过），但论文草稿里还有不少旧口径数字，要全部重算或删掉 |
| 2 | 每次运行上限 500 轮、3 小时（**有意为之**：陈润材 11-13 说明，他们发现官方上限太低，模型常常还没做完就被截断，放宽后能交出答案） | 这本身不算有害，但通过率和公开榜单没法直接比 | 保留放宽的上限；挑一批题，按官方上限和放宽上限各跑一次，统计「被截断、放宽后能做出来」的比例，把它变成论文里有数据支撑的发现 |
| 3 | 旧造题线：自己造题、自己加测试点，再让评委打分 | 容易出「废题」（测试点在题面里找不到依据）或太简单的题（便宜模型 grep 一下就过） | 已弃用，新题只用真实上游提交带的测试 |
| 4 | Opus / Fable 只在 DS、GLM 都失败的题上才补跑 | 强模型只在难题上有数据，四个模型之间比不公平（选择性缺失） | 修正案 A1 已写明不做无偏四模型比较，论文里也不能这么比 |
| 5 | 旧标签用「运行级平均分 < 99.999 就算失败」来代替逐条测试判定 | 不是官方的逐测试判定，只是近似；bax 来源只有 37% 的题有纯测试标签 | 只当历史参考；新题必须用逐条测试结果 |
| 6 | 开发集（467 道旧题）被反复用来调参 | 已经被「看过」，不能再当独立验证（研究者自由度） | 他们已承认；结论只能来自新题 |
| 7 | 适配层借用线上平台的 Python 环境 | 可能弄坏线上服务；环境也不可复现 | 新建独立环境 |

## 二、偏离官方，但必要、而且已经披露（可以保留）

| # | 做法 | 说明 |
|---|---|---|
| 8 | 自写「适配层」（把自定义题接进官方评测程序的转接代码） | 官方评测程序只认它自己登记过的题，自定义题必须自己写转接。修正案 A11 已披露；论文要写成「官方评测程序 + 自定义适配层」 |
| 9 | agent 运行时禁网，也看不到答案测试 | 和官方一致，这是防作弊的基本要求 |

## 三、比官方更严的改进（值得保留，甚至可以写成贡献）

| # | 做法 | 好在哪 |
|---|---|---|
| 10 | 「应该跑却被跳过的老测试」算失败（A10） | 官方报告不拦这种情况，可能被钻空子；他们加了审计 |
| 11 | 判官一题一调用、预测目标互不可见、先存哈希（文件指纹）再运行 | 他们发现过判官成片执行时的泄漏，这是踩坑后的规范 |
| 12 | 每题每模型跑 2 次，量化标签噪声 | 官方多数只跑 1 次；他们测出同题重跑有约 28% 结果不一致 |
| 13 | 预注册（事先写死要检验什么、怎么算，之后不改） | 防止看了结果再改分析方法 |
| 14 | 入库前三关预检：旧代码要挂、标准答案要过、空补丁要挂 | 接近 SWE-bench-Live 的做法，能挡掉标注有问题的题（surveyjs 就是这样被挡掉的） |

## 四、还缺、而官方或权威做法里有的
- **测试稳定性筛查**：多次运行剔除时过时不过的测试。他们只跑两次看是否一致，没有系统剔除。
- **测试点审查清单**：测试要能在题面里找到依据、不泄露答案。他们自己也承认不会做。
- **数字一致性**：00 号文档说评测主表 1525 行，DSH 实数是 1844 行，需要核对口径。
