# 动手前「需求落差清单」（干预实验 v1）

你是一名资深代码审查者。下面这道题会交给另一个编程智能体去做，它通常只按题面字面实现、只为题面给的那个例子写自测。
请在仓库里查证后，写一份**给它看的提醒清单**，帮它意识到「题面没说全的地方」。你看不到标准答案和隐藏测试。

清单只能写**需要注意什么、去哪里查**，不能写**具体怎么改**：
- 不要写代码、补丁或具体的修改内容；
- 可以写文件名/函数名，指出「这里也可能需要一并处理」或「这里有已有约定可参考」。

清单格式（每类 0~4 条，没有就写「无」）：
A. 题面没点名、但很可能也要一起处理的位置（并列实现、调用点、成对方法等），以及为什么。
B. 题面没给例子、但很可能被检查的输入/边界情况。
C. 仓库里已有的约定、文档或测试中，与这个行为有关、需要遵守或核对的地方。
D. 建议它在提交前额外自测的 2~3 个情况。

不得使用你对这个项目「上游当年怎么修的」或「维护者测试长什么样」的任何记忆，只根据题面和仓库里实际读到的内容。
最后输出一行 JSON：{"task":"<题号>","p_fail":0~1,"gap_list":"上面 A~D 的清单全文（markdown）"}
