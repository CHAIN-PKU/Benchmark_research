# DS 经验卡 v2（什么条件下才致命）

来源：DS 在旧题上的 232 道成绩、42 道有效挂题的三层归因（看了 DS 的操作记录）、以及和「有同样风险但做对了」的题对照。只写规律和条件，不含任何具体题的答案。

## 一、整体水平（用来定基准概率）
- 这类真实仓库任务，DS 大约 75%~80% 能做对；两次都挂的只有约 15%。
- 先从「大约 20%~25% 会挂」出发，再按下面的条件上调或下调。没有命中任何致命条件时，不要高于 30%。

## 二、DS 的做事习惯（从操作记录看到的）
1. 照题面字面实现，很少质疑题面给的期望或建议的改法。
2. 会写测试、会跑测试，但自测只覆盖题面给的那一个例子。
3. 在症状出现的地方修，不太往上追是谁产生了错误的值。
4. 熟悉的、约定俗成的成对结构（同一功能的两套实现、读写成对）它通常会一起改。

## 三、致命条件（命中才明显上调；只是「有这类风险」不算）
A. 隐藏要求（最稳定的挂法，两次都挂的大多是这类）
   致命：题面写了期望（示例、表格、建议行为），但仓库现有的测试、文档或参考实现与题面字面不一致；或正确行为只在某个条件下成立而题面没写这个条件（只在 HTTPS、某平台、某配置开启时）。
   不致命：题面期望和仓库约定一致，或仓库没有相关约定。
B. 并列漏改
   致命：需要同样改动的另一处，题面没有提到，并且在不同的方法、类或文件里，搜索被改函数名或那行写法才能找到。
   不致命：成对结构是这个仓库的固定套路（每个功能都有两套实现），或另一处就在同一函数、相邻几行。
C. 题面说窄了
   致命：题面只举一个例子或带限定词（某平台、某个值、某个修饰符），而仓库里相关逻辑本来是通用的，正确修法要覆盖整类输入。
   不致命：题面例子就是唯一的情况，或题面明确说了范围。
D. 修症状
   致命：题面描述的是下游症状（显示重复、输出错位），而错误的值是上游某处产生的，症状处修补也能让题面例子通过。
   不致命：症状处就是根因。
E. 边界值
   致命：正确性取决于一个边界（等号还是不等号、空和只有空白、0 和缺省），而题面没说清，自测只用题面的例子测不出来。

## 四、下调条件（这些情况 DS 通常能做对）
- 改动集中在一两个函数，题面给了可复现的例子，且这个例子就是测试要的行为。
- 题面给了明确的位置或修法，且和仓库约定一致。
- 「测试可能更严」「可能有边界情况」这类每道题都能说的担心，不算命中，不要因此上调。

## 五、怎么给概率
- 没命中任何致命条件：0.10~0.30。
- 命中一条且有仓库证据：0.35~0.55。
- 命中 A，或命中两条以上且都有证据：0.55~0.80。
