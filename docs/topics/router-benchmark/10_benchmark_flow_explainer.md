# 跑一次编程 Benchmark 的完整流程（大白话版，给 crc 汇报用）

2026-11-14 · Claude Code 整理 · 例子都来自我们这两天真实跑 DS 的经历

---

## 一、一句话
拿一批「真实 GitHub 上修过的 bug」当考题，让模型在一个**沙箱**（隔离的小电脑，不能上网、看不到答案）里自己改代码，最后用**官方评测程序**（自动阅卷机）跑测试，**全部该过的测试都过了才算做对**。

## 二、一道题由什么组成
| 名词 | 大白话 |
|---|---|
| issue / 题面（problem statement） | 用户报的 bug 描述，模型只能看到这个 |
| base commit（基线版本） | 修 bug 之前那一刻的代码，模型从这里开始改 |
| gold patch（标准答案） | 当年开发者真正提交的修复，**绝不给模型看** |
| test patch（测试补丁） | 当年一起提交的新测试，用来判卷，**也不给模型看** |
| F2P（Fail-to-Pass，该修好的测试） | 改之前挂、改对之后必须过的测试，考「修没修好」 |
| P2P（Pass-to-Pass，不许改坏的测试） | 本来就过的老测试，改完还得过，考「有没有改坏别的」 |
| 镜像（Docker image） | 打包好的运行环境（语言、依赖都装好），保证每次判卷环境一模一样 |

**判分规则（官方）**：F2P 全过 **且** P2P 全过 = resolved（做对）。没有部分分，也不加权。

## 三、完整流程（我们实际怎么做的）
1. **选题、冻结题单**：从官方题库（SWE-bench 多语言版 + 精选版，350 道）选题，按固定随机种子分组，算出**文件指纹**（SHA256，文件的「身份证号」，改一个字就变）。之后不许再改题单。
2. **分组**：
   - **提炼组**（训练用）：让 DS 跑，用来找「DS 在什么题上容易挂」的规律；
   - **盲测组**（考试用，83 道）：先用我们的方法**写下预测并冻结**，再让 DS 跑，揭晓准不准。顺序反了就作废。
3. **预检**（不跑模型，只检查）：题在不在、语言能不能识别、镜像能不能拉、Python 题有没有环境。
4. **自检**（每道题跑模型前）：
   - 打上标准答案 → 必须做对；
   - 什么都不改 → 必须做错。
   - 两条都满足，说明这道题本身能判卷。（rubocop-13653 就因为标准答案都过不了被排除。）
5. **让模型做题**：在沙箱里跑，上限 **500 轮 / 3 小时**（我们特意放宽，官方上限常把模型「掐断」）。每道题**跑 2 次**，看结果稳不稳。
6. **防作弊检查**（我们叫「闸门」）：检查模型有没有偷看未来的代码历史、联网找答案。结果分：干净 / 拿不准 / 作弊（作弊的作废）。
7. **判卷**：把模型的改动交给官方评测程序，在镜像里跑 F2P 和 P2P，得出做对/做错。
8. **记账**：每次都记轮数、用时、token（模型读写的字数）、花费、镜像指纹、走的哪条接口。
9. **汇总**：每道题两次的结果 → 0/1/2 次做对；作废、环境故障的单列，不算进失败率。

## 四、我们踩过的坑（老师很可能问）
1. **旧标签不可靠**：同一道题，旧记录说 DS 挂了，重跑两次都过（或反过来）。3 道试跑翻了 2 道。→ 所以每题跑 2 次。
2. **接口不同、结果不同**：同一个 DS 模型，走 OpenRouter 和走 DeepSeek 官方接口，有的题结论相反（caddy-6051、fmt-3158）。→ 主数据只用一条接口，另一条当对照，写成「接口敏感性」。
3. **作弊检查会误判**：把模型读自己的聊天记录、或用只读的 git 命令（merge-base）当成作弊。→ 修了规则，每次改判都留旧结论、新结论、时间、脚本指纹。
4. **环境故障 ≠ 模型做错**：网络断了、磁盘满了、端口被防火墙挡了，模型一步没走就结束。→ 这类记「环境故障、不计」，补跑。
5. **磁盘会爆**：大项目（Rust、Node）编译产物一次 5~10G。→ 磁盘 90% 自动停、跑完一道清一道、大项目最后单独跑。
6. **镜像下载有限额**：Docker Hub 匿名每小时 100 次，超了报 500（像网站坏了，其实是超额）。
7. **成本口径**：账户余额差会混进别的开销；按 token × 官方单价算的才是跑题本身的花费。
8. **不能按结果挑题**：失败题少也不能专挑难题补、不能放宽判定，只能靠扩大题量。否则审稿人会说数据被挑过。

## 五、现在的数字（11-14 上午）
- 已跑完 55 道左右（每题 2 次）：大多数两次都做对，6 道两次都挂，5 道一过一挂。
- 每次花费几分钱人民币；总共 350 道预计再 1 天多跑完。

## 六、老师可能问的问题 & 一句话回答
- **为什么只看「全过」，不给部分分？** 官方就是这样；部分分容易被「只修一半」钻空子。
- **怎么保证模型没背过答案？** 沙箱断网、截掉修复之后的历史、闸门查偷看；另外用「新仓库」盲测组看泛化。
- **预测怎么证明有用？** 预测在模型跑之前冻结（存指纹），再揭晓；和别人的方法（如 ADeLe）在同一批题上比准度。
- **为什么跑 2 次？** 同一题结果会变；两次能区分「稳定会/稳定不会/看运气」三类。
