# 课题一页纸：编程智能体「动手前」预测能不能做对（给 crc 和老师交流用）

2026-11-14 · Claude Code 整理（数字取自 DSH 15:37 的核对）

## 一、要解决什么问题
新来一道编程任务（真实 GitHub 上的 bug），**在让模型动手之前**，就预测某个模型（先做 DeepSeek，简称 DS）能不能做对。
- 用处：做对的把握大，就派便宜模型；把握小，才派贵模型。**省钱又不掉成功率**。
- 现状：大家通常是「每个模型全跑一遍再看分数」，贵；已有的预测方法（如 Nature 上的 ADeLe）做的是问答题，没做到「整个代码仓库级」的编程任务。

## 二、方法（我们怎么预测）
1. **攒数据**：让 DS 在几百道真题上各跑 2 次，记下每道题「两次里做对几次」（0 / 1 / 2）。
2. **找规律**：逐个看 DS 做挂的题，总结「遇到什么样的题、仓库里有什么，DS 就容易挂」（比如题面只给了一个场景、正确修法要更通用；要改坏老测试才能修好等）。每条规律至少 3 道题支撑，并记下反例。
3. **做预测**：一个强的「决策模型」读题面和整个仓库，对照这些规律，给出「DS 能做对的概率」。
4. **验证**：在一批**从没碰过的盲测题**上，先把预测写死（存文件指纹），再让 DS 跑，揭晓准不准。

## 三、实验规模（目标）
| 项目 | 计划 |
|---|---|
| 题目 | 350 道官方题库真题（8 种语言）：提炼组约 267 道，盲测组 83 道（含 27 道来自没见过的新仓库） |
| 每题重复 | 每个模型每题跑 2 次 |
| 模型 | 先 DS 做完整流程；之后加 2~3 个便宜模型（GLM、Haiku）赶 ICML；完整版 6~7 个模型（加 Sonnet、Opus 等）留给 NeurIPS |
| 对照方法（baseline） | 至少 5 个：①按仓库/语言猜；②题面转向量+简单分类；③大模型直接读题判断；④让模型自己评估；⑤ADeLe 和 IRT（按题难度和模型能力打分的统计方法）类 |
| 消融（逐个拿掉，看各自贡献） | 去掉读仓库；去掉「从失败里挖的规律」；换一个决策模型；减少用来画像的锚定题数量 |

## 四、看什么指标、做到多少才敢投
（这是目标，不是保证；做不到就如实写成负结果或换投数据集赛道）
1. **准度**：AUROC（预测打分准不准，0.5 = 瞎猜，1 = 全对）在盲测组上达到 **0.75 以上**，并且**比最强的对照方法高 0.05 以上**，置信区间不跨 0。
2. **校准**：预测「70% 能做对」的题，真的约 70% 做对。
3. **省钱**：用预测去给题目选模型，在成功率最多掉 2 个百分点的前提下，**省 30% 以上**的花费。
4. **泛化**：换 2~3 个其他模型，方法依然有效。
